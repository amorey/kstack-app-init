# sidecar — Go backend

A standalone Go binary started by the Tauri host. It exposes the app's GraphQL API (and a gRPC control channel) and owns all Kubernetes logic. **No TCP** — it listens on a Unix domain socket (named pipe on Windows), prints `READY unix:<path>` to stdout so the host can dial it, and shuts down on `SIGINT`/`SIGTERM` or **stdin EOF** (parent gone).

The data dir (`--data-dir` / `KSTACK_DATA_DIR`) is **required** — `app.New` errors when empty; tests supply `t.TempDir()`. `<data-dir>/app.db` is owned by `internal/appdb` (one migration sequence; add app-level tables as numbered migrations in `appdb/migrations/`, never a second embed against the same file).

## Layout

Mirrors the kubetail layout: `main.go` is lifecycle only, `internal/app` is the composition root + routing, GraphQL lives in `graph/`. There is no `server` package.

- `main.go` — parse flags, bind socket, build `*app.App`, serve, drive graceful shutdown (`srv.Shutdown` → `app.DrainWithContext` → `stop(ctx)` → `app.Close`).
- `internal/app/` — **composition root**: builds `poke.Service`, `cluster.New(...)`, `auth.Service`, `cloud.Service`; wires `graph.NewServer` + `grpcserver.NewServer`; multiplexes both onto one h2c handler (dispatcher keyed on `grpcserver.IsGRPCRequest`). `App.Start(ctx)` returns a drain-func; the stop chain is `clusterSvcStop → cloudSvcStop → pokeSvcStop` — poke's hub closes **last**, after its subscribers drain (the left-to-right arg evaluation in the `errors.Join` enforces it).
- `graph/` — `schema.graphqls`, generated code, resolvers, `server.go` (gqlgen handler, bearer-token plumbing, SSE shutdown lifecycle). Resolver deps must be non-nil — tests wire fakes; degraded behavior lives inside the services, not behind nil-guards.
- `grpc/` — gRPC surface: `AuthService` (`StartLogin`/`Logout` unary; `AuthStateWatch` server-streaming, joins the drain WaitGroup) and `PokeService` (unary `Poke` → `poke.Poke(SourceHost)`). Committed protoc output in `grpc/authpb/`, `grpc/pokepb/`; regenerate with `make proto`; **never hand-edit `*.pb.go`**. `IsGRPCRequest` lives here — it *is* the definition of a gRPC request.
- `internal/` — `ipc` (per-OS user-only endpoint), `k8shelpers` (`KubeConfigWatcher`), `atomicjson`, `logging`, `sqlitemigrate`, `appdb`, `poke`, `testutil` (test-only helpers, imported by no production code), plus the subsystems below.

## gRPC + GraphQL over one socket (h2c)

`internal/app` owns the topology (that two surfaces share one socket); `grpc/` owns the predicate. HTTP/1.1 GraphQL POST + SSE are untouched. An idle `AuthStateWatch` survives the 60s `IdleTimeout` via gRPC keepalive pings. The cluster surface is **GraphQL-only**. → [ADR: single-socket h2c](../docs/adr/2026-08-09-single-socket-h2c.md).

**Shutdown order** (from `main.go`): `app.NotifyShutdown()` (gRPC streams end on their serving context; each SSE request's context is cancelled per-request) → `srv.Shutdown` → `app.DrainWithContext` (waits both sub-servers' WaitGroups — essential for hijacked h2c gRPC streams `srv.Shutdown` can't see) → `stop(ctx)` → `app.Close()` (`grpcServer.Stop()`, `clusterSvc.Close()`). Traps: grpc-go's `GracefulStop` **panics** on the h2c path — `Stop` only runs after the drain; never cancel via `http.Server.BaseContext` — it would tear down the shared h2c connection carrying gRPC mid-stream.

## Cluster subsystem (`internal/cluster`)

One flat package fronted by **`ClusterService`** (`service.go`) — the single boundary; every beehive detail (store, names, owner chain, spec/status split, delta-watch mapping) and the cache files live behind it. Beehive (`github.com/amorey/beehive`, v0.22.0) is the control plane, hosting four kinds in an owner chain — `Cluster → ClusterCache → ClusterCacheGVRDiscovery → ClusterCacheGVRSync` — with GC cascade on delete. → [ADR: beehive control plane](../docs/adr/2026-08-09-beehive-control-plane.md).

Files (flat): domain types (`types.go`, `helpers.go`), controllers (`core_controller.go` + `connection_sentinel.go`, `cache_controller.go`, `cache_gvr_discovery_controller.go`, `cache_gvr_sync_controller.go`, `cache_sync_workers.go`), the kubeconfig importer (`kubeconfig_importer.go`), the service boundary (`service.go`) and the units it composes (`cache_watch_loop.go` — the shared bind + debounce half of every per-cache stream; `sync_health_acc.go` — the per-cache verdict fold; `filter_chan.go` — the undecided-frame-holding channel filter), and the per-cache client policy (`cache_client_config.go` + `cache_idle_timeout.go`). Each `*_test.go` sits beside the file it covers. Leaf sub-packages under `internal/cluster/cache/` (none importing the root): `store` (SQLite cache `Manager` — reads + lifecycle), `kubesync` (the list/watch sync machine), and its specializations `eventsync`/`objectsync` (writes). All cluster tests are **white-box** (`package cluster`); shared fixtures live in `testutil_test.go` (in-package to avoid an import cycle, `_test.go` so the deps stay out of the production build).

### Identity & domain types

- `ClusterID` **is** the beehive ObjectID — opaque, source-agnostic, stable for the record's life; never the remote UID or the context name. The context's natural key lives only on the beehive **name** (`kubeconfig/{context}` — a uniqueness key, never read back for lookups). One shared GraphQL `ObjectID` scalar (decimal string) carries every kind's id; frontend codegen maps it to `string`.
- `ClusterSpec` is user/API-owned (`Name`, `Enabled`, `SyncEnabled`, `Source` — a discriminated union, kubeconfig today). The matching *observation* (names, presence, isDefault) is written live to `ClusterStatus.Source` by the core controller each reconcile, never spec. `Enabled` gates `ConnectionEligible`; `syncEligible = Enabled && SyncEnabled`. The spec carries **no trigger/counter fields** — retries and resyncs ride out-of-band buses, never spec writes.
- `ClusterCache.Spec.ServerUID` names the physical identity the cache mirrors. **Active-ness is deliberately not a field** — the client derives it by joining against the cluster's live `status.server.uid` (→ [ADR: delta watches](../docs/adr/2026-08-09-delta-watch-protocol.md)). A cluster owns zero or one cache at steady state; a UID migration creates the new identity's cache and prunes the old.
- A future cluster-creator = a new `ClusterSpecSource` variant + a sibling importer + a credential-resolution case in the core controller. Reintroduce a separate intake kind only if two sources must dedup into one Cluster.

### Conditions

Every condition is a **liveness** condition (`liveCondition` in `types.go` is the only constructor); beehive serves a previous process's write as `Unknown`+`Unconfirmed` until re-confirmed. **`Unconfirmed` is load-bearing on the wire**: the surviving reason/stamps describe *last-known* state — consumers (e.g. the sync panel) must not render a pre-restart reason or `transitionedAt` as current. Controllers ignore the flag and overwrite unconditionally (`syncWasRunning` deliberately reads the pre-restart reason). A pass writes its whole `conditionSet` transactionally with its status (`SetConditions` inside `client.Within`, plus `UpdateStatus` or `SetObservedGeneration` — a condition write alone does **not** settle a generation, so skipping the handshake leaves the object owed forever). `cluster.Condition` aliases `beehive.Condition`; conditions sit beside `status` on the wire, bound directly. → [ADR: liveness conditions](../docs/adr/2026-08-09-liveness-conditions.md).

### Status, gauges, events

**Status is a propagation channel, not a place to keep gauges.** `ClusterCacheStatus`, `ClusterCacheGVRDiscoveryStatus`, `ClusterCacheGVRSyncStatus` are empty structs; measurements live in controller memory, served via `Service.GVRSyncStats`/`GVRDiscoveryStats`/`CacheStats` as `stats` resolver fields. A settled child writes nothing (`TestGVRSyncFoldsWorkerReports`, `TestGVRDiscoverySteadyPassWritesNothing` pin the resource_version) — don't add hot-path status writes. Live measurements ride their own streams keyed to what changes them: `clusterCacheStatsWatch` (cache contents gauge — never the `ClusterCache.stats` field, which freezes at subscribe time; that field is read only for `exists`), `clusterScheduleWatch` (next-attempt countdown from beehive's `WatchSchedule`, merged with the controller's `Probing` flag via `mergeSchedule`), and the events surface below. → [ADR: status propagation & gauges](../docs/adr/2026-08-09-status-propagation-gauges.md).

**Generic events surface**: probe/sync history rides beehive's coalescing event log (runs upserted by `Event.ID`, retention `WithEventRetention(20, 0)`), keyed by object id and kind-agnostic — `clusterEvents(Watch)`, `clusterCacheEvents(Watch)`, `clusterCacheGVRSyncEvents(Watch)` (the sync-transition history lives on the per-kind child). This keeps per-probe chatter off `clustersWatch`: a repeated failure bumps a run's count without a status write (the core controller skips unchanged writes via `ClusterStatusEqual`).

**Whole-cache sync verdict**: `WatchCacheSyncHealth` → `clusterCacheSyncHealthWatch` is a **read-side fold** (one process-wide fold, latest-value hub carrying the whole verdict map; started lazily, stopped via `stopSyncHealthFold` before beehive stops). Worst-reason-dominated (SyncFailed > Stale > NoConnection > Syncing > Paused), `unhealthyResources` as a sorted list (the client keys on the first offender — never render prose it must parse back). Unconfirmed/unreported children fall to `Unknown`/`Syncing` — absence of an observed fault is not observed health. A cache whose discovery anchor is gone is dropped from the map; the client derives deletion from `clusterCachesWatch`, not a delete frame. Recomputes on frames **and** a 10s tick (the freshness stamps move with no frame behind them), only for dirtied caches.

### Controllers

`WithStartupFullPass(true)` on all four kinds (each owns process-scoped state a restart invalidates but never wrote); **no** periodic full pass — controllers re-arm via `RequeueAfter`, out-of-band triggers cover the rest.

- **ClusterCoreController** — observe kubeconfig into `status.Source` → eligibility gate → resolve credentials → identity probe (ServerVersion, kube-system UID, SelfSubjectReview) → `/readyz`, folded into `Connected`/`Healthy`. Probe failure returns an error so beehive backs off (1s ×2 cap 2m); success returns the ~30s cadence. After a successful probe: `ensureClusterCache` for that UID, then `pruneSupersededCaches` — both gated on a **confirmed** UID (a transient disconnect never prunes); create/prune errors are non-fatal. **Per-cluster locks + fresh re-read under lock** (beehive status writes carry no RV guard); distinct clusters reconcile in parallel, bounded by `clusterProbeConcurrency` (8). Out-of-band triggers (one background worker, `StartBackground`/`StopBackground`): the retry bus (`Reprobe` — from the sentinel and `Service.RetryConnection`; **backoff-neutral**, only a successful probe clears backoff), the resync poke bus (re-reconcile all), and the kubeconfig watcher (re-reconcile all; the status write wakes cache dependents). **Connection sentinel** (`connection_sentinel.go`): one liveness watch on kube-system per connected cluster, keyed by connection fingerprint; reacts only to the stream closing → one `Reprobe`. Down clusters run no sentinel. `ConfigureKubeHTTP2Keepalive()` (called once by `internal/app`) tightens client-go h2 health checks to 10s/5s so the sentinel fires in ~15s. → [ADR: connection probing](../docs/adr/2026-08-09-connection-probing.md).
- **ClusterCacheController** — decides whether one cache syncs; finds its parent via the owner edge (`GetOwner`), declares `DependsOn` (fires on the parent's spec *and* status writes — eligibility reads the core controller's observations). Syncs only the **active** cache (`syncEligible && Spec.ServerUID == parent.Status.Server.UID`). **The sync anchor exists for the cache's whole life; a pause is a spec write, never a deletion.** This is the one place that evaluates the sync rule — it collapses it into the anchor's `Spec.Enabled`; children never re-derive it. Deletion path: wait for `ListOwned` empty (each child's `gvrSyncDrainFinalizer` proves its worker stopped), then delete the `.db` via `store.Manager` and clear the `kstack.io/cache-files` finalizer — a file-delete error keeps the finalizer so the next pass retries; the file is never orphaned, never deleted under a live writer. Records `SyncStopped` only on `syncSwitchedOff && syncWasRunning` (spec switches only — never eligibility flaps; survives restarts via the `Synced` reason).
- **ClusterCacheGVRDiscoveryController** — one anchor per cache; converges `ClusterCacheGVRSync` children onto the API server's answer (create/refresh/**delete** — an uninstalled CRD's child is deleted; a pause travels as `Spec.Enabled` on children that stay put). Children matched by deterministic name (`gvrsync/{discoveryID}/{apiVersion}/{resource}`), read back via `ListOwnedObjects`, spec-compared before `Update` (steady state writes nothing). **A partial answer never prunes** (`discovery.IsGroupDiscoveryFailedError` splits "gone" from "didn't answer" → add/refresh only + `DiscoveryPartial`); total failure touches no child. `syncableGVRs` drops subresources, non-list/watchables, and the non-canonical `events.k8s.io` spelling. Discovery can't be watched (no resourceVersion in the document) → polls at `gvrDiscoveryInterval` (5m); request bounded by `gvrDiscoveryTimeout` via rest-config copy. Seeds the `v1/events` child **before** anything that can fail or wait (`ensureEventsChild`, one spec constructor `eventsSyncSpec` shared with `syncChildren`). Writes no cache-store rows — each child owns its own `kind_catalog` entry.
- **ClusterCacheGVRSyncController** — one `objectsync` worker per child, one child per served kind (hundreds per cache). Steady state writes nothing; `WithConcurrency(gvrSyncConcurrency)` for startup volume; per-kind isolation means one forbidden CRD reports `Synced=False/Stale` alone. **A worker's identity is its connection fingerprint AND its kind** — a CRD recreated with the same plural but a new Kind is respecified in place, the old worker rebuilt and its rows `Forget`-ed. A pause keeps rows + catalog entry (resume from saved position); deletion drains behind `gvrSyncDrainFinalizer` then `Forget`s best-effort outside the barrier (uses `Manager.Lookup`, never `Open` — re-opening mid-teardown would re-materialize the file).
- **Worker machinery** (`cache_sync_workers.go`) — the `workerSet` registry. Invariants: **drain-before-forget** (a failed drain keeps the entry, or a wedged goroutine could write to a `.db` being deleted); register-before-`Start` with the matching latch in `kubesync.Worker.Stop` (a stop landing in the window makes the later `Start` a no-op); a **per-object lifecycle lock** held across each whole stop-then-start sequence (a pause/deletion landing in the gap would report done while a restart puts a worker back); `syncSink` guards out-of-band reports by entry-pointer identity under `writeMu`. `syncedCondition` maps reports → `Synced`; `recordSyncTransition` records events only on a `(State, Cause)` change.
- **Kubeconfig importer** — **sole creator of `Cluster` objects, creation-only**: consumes watcher snapshots, creates missing contexts with name `kubeconfig/{context}`, writes only the `Source` reference. Never updates, orphans, or deletes — departure is the core controller flipping `IsPresent=false`; a returning context reuses its `Cluster`.
- **Kubeconfig watcher** (`internal/k8shelpers.KubeConfigWatcher`, instance owned by `cluster.New`) — fsnotify + 100ms debounce over the precedence paths, latest-value hub (current-on-subscribe). Consumed via the package-local `KubeConfigSource` interface (tests substitute a static fake).
- **Per-cache client policy** (`cache_client_config.go`) — the shared budget for every client built on a cache's behalf: a `flowcontrol` `RateLimiter` (set as `RateLimiter`, **not** QPS/Burst — nil fields give each of ~300 REST clients a private token bucket, bounding nothing), the shared `kubesync.ListLimiter`, and a 2-minute idle-read timeout on non-watch requests. Handed to both sync workers and discovery via `controllerRuntime.policies()` — the only reason it bounds anything.

### Per-cluster cache (`internal/cluster/cache/store`)

One SQLite file per cache incarnation at `<dataDir>/clusters/<ClusterID>/<CacheObjID>.db`, addressed by `store.CacheRef` (beehive ObjectIDs; AUTOINCREMENT so delete+recreate never reuses a path). `Manager` API: `Open` (integrity check → quarantine corrupt as `.corrupt-<stamp>`, embedded migrations, janitor)/`Lookup`/`WatchDB` (latest-value handle stream across open/close/replace — long-lived readers bind through it, never once to `Lookup`)/`CacheBytes`/`ResourceStats`/`Kinds`/`Events`/`Objects`/`DeleteCacheFiles`/`Shutdown`. Shared write helpers: `ResumeCookie` (per-collection list/watch position in `cluster_meta`) and `EnsureKindCatalog`. Schema: `objects` + `owner_refs`/`labels`/`status_history`/`events`(+FTS)/`kind_catalog`/`kind_counts` (trigger-maintained exact per-kind counts — reads are O(kinds), never scans)/`cluster_meta`; `raw_json` zlib-compressed. Janitor: status-history TTL + incremental vacuum; **events are not janitor-managed** (retention is server-mirrored by the relist prune). → [ADR: per-cluster SQLite cache](../docs/adr/2026-08-09-per-cluster-sqlite-cache.md).

**Two independent coalescing write-notify buses** per `ClusterDB` (`writeBus`, over **`gobus/watch`** — the keyed latest-value bus beehive builds its own `signalHub` on): objects and events, separate so an event burst never wakes object re-reads. The object bus is **resource-routed** — subscribe across every key (kind-catalog watch, `WatchAcross`) or to one `(apiVersion, resource)` (`Watch`); a notify wakes that key's subscribers plus every across one. The routing key is the **plural resource, not the Kind** (stable across a CRD Kind remap). There is deliberately **no wake-everyone notify**: every write path knows the resource it wrote, including the catalog upsert in `EnsureKindCatalog`. Subscribers are woken through a feeder goroutine, so a ping is *not* synchronously pending when the write returns — a test asserting one must wait for it, never `select`/`default`. Close the **sender**, never the hub (`Hub.Close` is a hard tear-down with no drain, and `Sender.Close` is the one the bus permits concurrently with a `Send`). `newCacheRef` is the one `beehive.ObjectID→int64` conversion point (keeps `store` beehive-free).

### The sync machine (`kubesync` / `eventsync` / `objectsync`)

`kubesync` mirrors one collection into one table and is ignorant of which: caller supplies a `Source` (`NewDynamicSource(cfg, gvr)`) and a `Store`; the package owns the resume/full-list state machine, the resync strategy, the error budget, graded liveness, and the LIST-phase `WithListLimiter`. Design: **watch-for-latency, poll-for-correctness** — edge cases self-heal within one interval rather than being closed exactly. → [ADR: kubesync watch/poll](../docs/adr/2026-08-09-kubesync-watch-poll.md). The invariants tests pin:

- **The cookie means "a full LIST completed on disk"**: first `WritePage` deletes it in the same transaction as the first rows; only `Commit` rewrites it.
- Relists prune by **mark-and-sweep**; the mark is 1ms past session start (`TestReplacePrunesRowsWrittenInTheSameMillisecond`).
- `Store.ApplyChange` advances the cookie in the row's own transaction — no trailing `PersistRV` (that path is for bookmarks only).
- Bookmarks are tapped ahead of RetryWatcher (`watch.Filter`), advance the cookie only after preceding deltas applied and only in the current watch epoch.
- Liveness proofs are **graded** (`lastWriteAt`/`lastProofAt`/`firstConnectAt`); a connect is weak — it opens an episode, never refreshes freshness, and **establishing is not error-budget credit** (a connect-then-die loop must age into `StateStale`/`CauseWatchNotStreaming`, not report `Watching` forever or refill the budget). `defaultEstablishTimeout` (30s) bounds the connect wait; exhausted budget → stuck, 3m retry cadence. The 30s `livenessMonitor` tick reports staleness with a cause; `Status.CaughtUpIn` zero distinguishes a heartbeat re-report.
- Warm resyncs use the metadata **diff** path where the store supports it (`MetadataDiffStore` — `objectsync` does, `eventsync` doesn't); falls back to the paginated full LIST for cold caches, no metadata endpoint, or deltas past `defaultDiffThreshold`. Jittered 30m re-list (`defaultResyncPeriod`) backstops everything.

**Reporting**: workers report through their `Sink`; the controller folds each report into `Synced` and the event log (start/complete vocabulary split on `ColdStart`; events only on a `(State, Cause)` change; `LastUpdateAt` = writes only, `LastLiveAt` = strong proofs, both carried forward).

**`objectsync`** (one per kind): kind-scoped statements against the shared `objects` table. A write lands object + edges (delete-then-insert, ≤2 statements per edge table) + `status_history` (transitions only) + cookie in one transaction, then pings resource-keyed. Bodies are sanitized at **write** time: `metadata.managedFields` + kubectl last-applied stripped, **Secret values redacted** (keyed on the *body's* kind, so it can't be bypassed by addressing). `Count` reads `kind_counts`, never scans. Materialized status columns (`status.go`) exist for SQL queryability, not the dashboard (which derives cells client-side from `rawJSON` — → [ADR: RawJSON scalar](../docs/adr/2026-08-09-rawjson-comparable-scalar.md)); all nullable. Each worker upserts its `kind_catalog` row in `New` and `Forget` drops rows+edges+catalog+cookie together; both ping the broker.

**`eventsync`**: events are an **ordinary synced kind** — same controller/worker/state machine, different store (own columns + FTS, server-mirrored retention, dedicated broker, both API spellings normalized to one uid-keyed row — which is why discovery keeps only canonical `v1`, keyed on group+plural via `isAltEventsKind`, never the Kind name).

### GraphQL surface (cluster)

The schema **is** the domain shape — every GraphQL type binds 1:1 by name to its `internal/cluster` type in `gqlgen.yml`; no projection layer. Resolvers are one-liners delegating to `r.ClusterSvc` (named to avoid shadowing the generated `Clusters` method). Key entry points:

- Delta watches: `clustersWatch`/`clusterCachesWatch` (independent; joined client-side), `clusterCacheGVRDiscoveriesWatch` (unscoped, one per cache), `clusterCacheGVRSyncsWatch(cacheID)` (cache-scoped — ~100 records; the always-mounted registry must not carry it), `clusterCacheSyncHealthWatch` (the fold).
- Cache-data watches (all keyed by cluster id + cache id; frames carry `cacheID` provenance — objects additionally `apiVersion`/`resource` — so the client rejects stale frames after a swap): `clusterDataKindsWatch` (kind catalog + counts; subscribes to **both** brokers via `catalogSubscribe`, since Event counts come from event triggers), `clusterDataEventsWatch` (newest window, `Deleted` when aging out), `clusterDataObjectsWatch` (per-kind rows incl. `rawJSON`; resource-keyed broker subscription). All share `cacheDeltaWatch[T]` (WatchDB rebind + debounce + keyed diff; `T comparable` — which is what makes body edits surface as `Modified`); gauge variant `cacheGaugeWatch` backs `clusterCacheStatsWatch`. Debounces (`service.go`): kinds/objects 250ms, events 500ms (`defaultData*Debounce`). Unopened cache → no frames.
- Events/schedule: `clusterEvents(Watch)`, `clusterCacheEvents(Watch)`, `clusterCacheGVRSyncEvents(Watch)`, `clusterScheduleWatch` (countdown + `probing`).
- Mutations: `clusterEnabledSet`, `clusterSyncEnabledSet`, `clusterConnectionRetry` (returns immediately; outcome lands on conditions), `clusterCacheClear` (delete files then **bounce that cache's workers** — nothing else would rebuild them; they cold-sync, the cookie died with the file), `clusterDelete` (GC cascades; a still-present context is re-imported under a fresh id).
- `ClusterDataEvent.type` is a plain `String!` (k8s doesn't constrain it) and timestamps are nullable `Time` via `nilIfZeroTime` (`graph/util.go`) — the domain keeps value `time.Time` for comparability.

Frontend join: `src/lib/clusters.tsx` (`ClustersProvider`/`useClusters`) reduces the three unscoped streams and joins `activeCache` + `syncHealth` client-side; `cluster-sync-panel.tsx` renders it (per-row detail streams subscribe only while a row is expanded; the sync column reads the rollup's reason, never the cache's coarse `Synced`).

## Auth / identity (`internal/auth`)

Local-first accounts against kstack-cloud's Hydra (`https://oauth.kstack.sh/`). The sidecar owns the whole flow: system browser (auth-code + PKCE, loopback redirect), exchange + verify (go-oidc vs JWKS; identity from the verified ID token), refresh token in the OS keyring (`keyringStore` over `zalando/go-keyring`). Signed-in ⇔ refresh token present; works offline. No gRPC credentials channel. Degrades to signed-out when unconfigured. → [ADR: local-first auth & settings](../docs/adr/2026-08-09-local-first-auth-settings.md).

- Root `package auth` is deliberately flat, organized by file: `auth.go` (the `Service` interface + `New(Config)`, `State`/`TokenSet`, `Token`/`Identity` aliases), `grant.go` (the grant aggregate — token set as source of truth, `Authenticated`/`Identity` **derived**, lazy refresh with burst-dedup, persist-before-cache, latest-value `State` hub), `login.go` (`loginFlow`: synchronous setup — loopback bind + browser open — returning its error to the mutation; the slow tail runs in a bounded detached goroutine, observed via `authStateWatch`), `keyring.go`.
- The one carved-out sub-package is `auth/oauth` — the OAuth2/OIDC protocol layer, a **leaf** (must not import `auth`). It owns `Token`/`Identity` (root re-exports as true aliases to avoid the cycle).
- `Config` carries only production knobs; **test seams are unexported functional options** on an unexported `newWithOptions` builder (white-box tests only). External consumers fake the `Service` interface. No `Start`/`Close` — no long-lived goroutines; `Logout` clears locally first, revokes fire-and-forget (keychain-write failure → error, stays signed in).
- `TokenSource(ctx)` returns an `oauth2.TokenSource` (nil when degraded); it exposes the refresh token — consumers read `AccessToken` only. The GraphQL projection drops tokens (`AuthState { authenticated, identity }`).

## Cloud settings sync (`internal/cloud`) — depends on `auth`

Local-first settings: an edit applies to a local JSON file immediately and queues durably for the cloud. **`cloud` depends on `auth`, never the reverse** — it authenticates from `authSvc.TokenSource` and wakes on `authSvc.Subscribe()`, tracking only the `Authenticated` bit (a token refresh is a non-event). Degrades without a data dir or cloud URL. `Start` is idempotent; its `stop` replaces `Close`.

Sub-packages (leaf-first): `syncstore` (generic `Envelope[T]` + `Store[T]` over `atomicjson`), `prefs` (`Settings` — pointer fields + omitempty so absent ≠ cleared; `Merge`; store deep-copies at boundaries), `mutationqueue` (durable FIFO, survives restart), `api` (GraphQL-over-HTTP client, per-request `TokenSource`), `prefsync` (the reconcile `Engine`: supervised connection with backoff + poke; `Watch` returns data + a buffered terminal-error channel so an errored close keeps escalating backoff; on Live drains the queue, and incoming snapshots get pending patches re-layered via `prefs.Merge`). Test seams: unexported functional options, same pattern as `auth`.

## Resync broadcaster (`internal/poke`)

A cross-subsystem **leaf**: a wall-clock gap detector (15s tick, 2× factor — catches sleep/SIGSTOP/VM pause, works headless) plus a `gochan/broadcast` fan-out hub. `New()` takes no arguments; `Start(ctx)` returns a stop func; `Poke(src)` never blocks. Consumers subscribe directly: the core controller re-probes all clusters, the GVR-sync controller bounces workers in place (cheap cookie resume), `prefsync` reconnects. **A poke is a fan-out, not a cascade** — never routed through spec counters or conditions (a clean resume produces no condition transition, so a cascade would silently skip the stale watches). → [ADR: poke resync fan-out](../docs/adr/2026-08-09-poke-resync-fanout.md).

## GraphQL via gqlgen — the schema is the source of truth

`graph/schema.graphqls` is authoritative — also consumed by the frontend's codegen (`codegen.ts`). After editing:

```sh
cd sidecar && go run github.com/99designs/gqlgen generate
```

This rewrites `graph/generated.go` + `graph/model/models_gen.go` and appends panicking resolver stubs to `graph/schema.resolvers.go` — implement those. **Never hand-edit `generated.go`/`models_gen.go`.** `tools.go` pins gqlgen. ## Patterns

- **Resolver deps are always non-nil** — the composition root wires every field; tests use fakes.
- **Pub/sub**: two modules, split on whether delivery is **keyed**. Unkeyed → `github.com/amorey/gochan`: `watch` for latest-value current-state streams (current snapshot on subscribe: kubeconfig watcher, auth `State`, `store.WatchDB`), `broadcast` for fan-out where subscribers supply their own snapshot (poke). Keyed → `github.com/amorey/gobus`: `watch` for a keyed latest-value bus (the cache's write-notify buses). Note the two `watch` packages differ on registration — gochan's hub holds a seed and delivers it, gobus's takes the caller's already-read value as a baseline and never delivers it back. Never hand-roll a subscriber map.
- **Subscription resolvers** return a channel emitting the current snapshot first, then deltas (`mapStream` in `graph/util.go`; delta watches via the service's `watchListChan` pump). Honor `ctx.Done()`.
- **Unexported functional options** for test seams (`auth`/`cloud`/`prefsync`/`poke`): exported `New` takes production knobs only; `newWithOptions(cfg, opts...)` is reachable only from white-box tests.

## Tests & checks

- testify + `httptest`. Resolver-level tests stand up `graph.NewServer(&graph.Resolver{...})` + `POST /graphql`; h2c/lifecycle tests stand up `app.New(...)`. Filesystem via `t.TempDir()`.
- **White-box tests by default** (`package foo`, not `foo_test`) — boundaries are kept by discipline, not the compiler. Escape hatch: external `package foo_test` only when pinning the public contract is the test's purpose — then say so in a comment.
- **No magic sleeps** (repo-wide — see the root `CLAUDE.md` for the rule and its two carve-outs). Block on the actual event, never a fixed `time.Sleep`. A cadence a test would otherwise have to outwait becomes a **parameter** whose production value is the constant — `cacheWatchLoop` takes `debounceDur`/`retryDur` for exactly this — so a test picks its own timescale and never encodes the production number.
- **Waiting on a channel goes through `internal/testutil`**, which owns the one failsafe bound (`testutil.Timeout`): `Wait` (a done/ready channel), `Recv[T]` (the next value), `RecvClosed[T]` (the next receive must be a close), `WaitClosed[T]` (drain until close). Don't hand-roll a `select` with a `time.After` deadline. The exception is a **negative** assertion — "no frame arrived" — which needs its own short window, not the failsafe.
- **A fake that notifies the test uses `testutil.Signal` or `testutil.Probe[T]`**, never a hand-rolled channel. `Signal` (a `gochan/oneshot` pair) is single-shot: `Fire` is idempotent by contract, so a callback that runs many times needs no `sync.Once` and no `select`/`default` guard, and `Fire`'s bool tells the first call from the rest. `Probe[T]` is the repeating case: `Fire` never blocks (a fake that blocks stalls the code under test) and drops the **oldest** on overrun, because the event a test waits for is the newest — which is exactly what a `select`/`default` send throws away. `Await`/`TryAwait`/`Drain`/`Chan` are the read side.
  - The exception is a consumer that does **edge detection**. `internal/cloud`'s auth subscriber swallows its first value as a baseline and acts on the next *change*, so its fake must deliver every state losslessly: a latest-value hub (`gochan/watch`, which is what the real `auth` service publishes through) or a drop-oldest `Probe` can both coalesce the seed with the change and hide the edge. Its `fakeAuth` keeps a plain buffered fan-out, and says so.
