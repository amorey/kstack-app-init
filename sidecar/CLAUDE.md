# sidecar — Go backend

A standalone Go binary started by the Tauri host. It exposes the app's GraphQL API (and a gRPC control channel) and owns all Kubernetes logic. **No TCP** — it listens on a Unix domain socket (named pipe on Windows), prints `READY unix:<path>` to stdout so the host can dial it, and shuts down on `SIGINT`/`SIGTERM` or **stdin EOF** (the host closing its end = "parent gone").

## Layout

The codebase mirrors the **kubetail layout**: `main.go` is lifecycle only, `internal/app` is the composition root + routing, and the GraphQL server lives in `graph` (alongside the resolvers). There is **no `server` package**; "the server" is the thin listener in `main.go`.

- `main.go` — **lifecycle only**. Parses flags, binds the socket, builds the `*app.App`, mounts it on an `http.Server`, registers `app.NotifyShutdown` via `srv.RegisterOnShutdown`, serves, and drives graceful shutdown (`srv.Shutdown` → `app.DrainWithContext` → `app.Close`). No composition logic.
- `internal/app/` — **composition root + routing + lifecycle owner**. `app.go` (`app.New(Config{...})`) builds the shared pieces (the `*poke.Service`, then `cluster.New(...)` → `*cluster.Service` — which owns its own kubeconfig watcher and beehive store/instance — plus `auth.Service` and `cloud.Service`), constructs the `graph.Resolver` (holding the `ClusterService` + `auth.Service`), wires the GraphQL server (`graph.NewServer`) and gRPC server (`grpcserver.NewServer`), mounts them on a mux, and multiplexes onto one h2c handler: an `h2c.NewHandler` whose dispatcher sends `grpcserver.IsGRPCRequest` traffic to the gRPC server and everything else to the mux. It owns this *composition* — that these two surfaces share a socket and the h2c wiring itself — while `grpc/` owns the gRPC-request predicate. `App` is a thin `http.Handler`: it holds the two sub-servers and the services, delegating `Start`/`Close` to them and fanning `NotifyShutdown`/`DrainWithContext`/`Close` out to the sub-servers. `Start` order: `pokeSvc.Start` → `clusterSvc.Start` (starts beehive + watcher internally) → `cloudSvc.Start`. `Close` closes the poke broadcaster, then `clusterSvc.Close` (which owns the full watcher + beehive + cache teardown order internally) and cloud — app no longer sequences any cluster shutdown ordering.
- `graph/` — GraphQL: `schema.graphqls`, generated code, resolvers, and **`server.go`** — `graph.Server` (`NewServer(*Resolver)`), the gqlgen handler with the bearer-token plumbing, SSE shutdown lifecycle, and `NotifyShutdown`/`DrainWithContext` (see Shutdown below). The `Resolver`'s dependencies must be non-nil — tests wire fakes (e.g. a fake `auth.Service`); degraded behavior lives inside the services, not behind resolver nil-guards.
- `grpc/` — gRPC surface. `grpc/server.go`: `grpcserver.NewServer(authSvc, pokeSvc)` wraps a `*grpc.Server` (registering `AuthService` and `PokeService`; `AuthService.AuthStateWatch` is the lone server-streaming RPC and joins the `streams` WaitGroup so it drains at shutdown — `PokeService` is unary-only so it doesn't) with the `NotifyShutdown`/`DrainWithContext`/`Stop` lifecycle surface. `grpc/auth_server.go` implements `AuthService` over `auth.Service`: `StartLogin`/`Logout` (unary, nil-service → `Unavailable`) and `AuthStateWatch` (server-streaming, latest-value from `auth.Subscribe()`, nil-service → end immediately). `grpc/poke_server.go` implements `PokeService` over `*poke.Service`: one unary `Poke` (nil-service → `Unavailable`) that broadcasts `Poke(SourceHost)` — the host calls it on OS resume / network-on to resync long-lived connections. `grpc/authpb/` holds the committed protoc output for `proto/auth.proto`; `grpc/pokepb/` for `proto/poke.proto`. Regenerate all with `make proto` (or `go generate ./grpc/...`); never hand-edit `*.pb.go`. (Kube/cluster data is **not** a gRPC service — it lives only on the GraphQL surface: `clusters`/`cluster` queries, `clustersWatch` subscription, cluster mutations.) The predicate `IsGRPCRequest` lives in `grpc/server.go`; the composition root uses it to route the shared h2c socket.
- `internal/` — building blocks: `app` (composition root, above), `ipc` (binds the per-OS IPC endpoint — AF_UNIX socket / named pipe — with user-only access; `main.go` uses `ipc.Listen`/`DefaultSocketPath`/`Scheme`), `k8shelpers` (the kubeconfig watcher — `KubeConfigWatcher`, consumed by `internal/cluster`), `atomicjson` (crash-safe single-file JSON read/write), `logging`, `sqlitemigrate` (shared forward-only SQLite migration runner), `appdb` (owns the app-level `app.db` — its connection pool and single migration sequence — and hands the `*sql.DB` to consumers), **`poke`** (cross-subsystem resync broadcaster — see below), plus the **cluster** package under `internal/cluster/` (the Kubernetes/cluster subsystem behind `ClusterService` — see *Cluster subsystem* below), the **auth** packages under `internal/auth/` (the mostly-flat root `auth` package — `auth.Service`, the local-first identity layer — with the OAuth2/OIDC protocol layer carved into the `auth/oauth` sub-package), and the **cloud** packages under `internal/cloud/` (the root `cloud` package — `cloud.Service`, the cloud-synced settings feature that *depends on* `auth` — and its settings sub-packages; see *Auth / identity* and *Cloud settings sync* below).

## Cluster subsystem (`internal/cluster`)

The cluster subsystem is one flat package, `internal/cluster` (`package cluster`), fronted by **`ClusterService`** — the single boundary between the frontend and the cluster backend. Beehive (`github.com/amorey/beehive`) is the control plane: a SQLite-backed, level-triggered controller framework (a small operator runtime). The service owns its beehive store (at `<dataDir>/beehive.db`) and instance outright — beehive is cluster-only, so there's no reason for the composition root to hold it; if a non-cluster kind ever needs beehive, hoist the store/instance back up to `internal/app` and pass `*beehive.Beehive` into `cluster.New`. Beehive hosts two resource kinds in an **owner chain** — `Cluster → ClusterCache` — so deleting a cluster cascades (beehive GC) to its ClusterCache without finalizers. (There is no separate per-context intake kind: the kubeconfig importer reconciles contexts directly into `Cluster` objects, 1:1.)

The package holds (flat, by file): the **domain types** (`types.go`, `helpers.go` — the spec/status split, `ClusterID`, slugs, condition helpers, `ConnectionEligible`), the **two beehive controllers** (`core_controller.go` = `ClusterController`, `cache_controller.go` = `ClusterCacheController`), the **kubeconfig importer** (`kubeconfig_importer.go` — the sole creator of `Cluster` objects), and the **service boundary** (`service.go`). Two genuine deep modules are carved out as leaf sub-packages (the `auth/oauth` precedent), neither importing the root, grouped under `internal/cluster/cache/`: `internal/cluster/cache/store` (`package store` — the per-cluster SQLite cache `Manager`) and `internal/cluster/cache/engine` (`package engine` — the sync engine). The `cache/` parent is a namespace directory only (no Go files); the `ClusterCacheController` that drives these two stays in the root `cluster` package (it's glue — coupled to the root's beehive kind types + condition/eligibility helpers, and registered by `service.go` — so moving it under `cache/` would cycle). `internal/cluster/testutil` holds shared test helpers. White-box service tests live in `package cluster`; the controller tests are external (`package cluster_test`).

**`ClusterService` (`service.go`) is the boundary.** `cluster.New(dataDir, kubeconfigPath, pokeSvc) (*Service, error)` builds the kubeconfig watcher (over `kubeconfigPath`), opens the beehive store + instance (at `<dataDir>/beehive.db`), builds the two beehive clients (one per kind), constructs and **registers the two controllers** with beehive, and builds the importer and the per-cluster cache `store.Manager` (rooted at `<dataDir>/clusters/`); the returned `*Service` implements the `ClusterService` interface — the GraphQL-facing domain surface: `List`/`Get`/`Watch` (each joins the ClusterCache sync status; `Watch` merges the Cluster + ClusterCache `WatchList` channels and re-emits the full list on any change), `CacheStats`, `SetSyncEnabled`/`RetryConnection`/`ClearCache`/`Delete`. Every beehive detail (the store itself, slugs, the owner chain, the spec/status split, the cache-status join, the watch merge, generation-bump signals) and the cache files live behind it; callers deal only in the domain `Cluster`. `*Service` additionally owns the full control-plane lifecycle off the interface: `Start(ctx)` starts beehive, then the importer and the **poke→sync forwarder** (bumps `Spec.PokeSyncGeneration` on every Cluster so running engines bounce); `Close(ctx)` tears down in dependency order — close the watcher + stop the writers (importer + forwarder), stop beehive (every controller + sync engine), shut down the cache (safe only now the engines are gone), then close the beehive store. The composition root (`internal/app`) holds the concrete `*Service` (for `Start`/`Close`), hands it to `graph.Resolver` typed as the interface, and owns only the shared poke bus — it no longer sequences any cluster-shutdown ordering, since that invariant now lives entirely inside `Service.Close`.

Adding a future cluster-creator (manual creation, kstack-cloud sync) means a new `ClusterSource` *variant* (the discriminated union on `ClusterSpec.Source`) + a new importer peer writing `Cluster` objects with that variant + a sibling block in `ClusterSourceStatus`, plus a per-variant credential-resolution case in `ClusterController` (today it hard-codes the kubeconfig variant). All creators share the one `Cluster` kind; reintroduce a separate intake kind only if two sources must ever *dedup* into one `Cluster` (e.g. a kubeconfig context and a cloud record naming the same physical cluster) — until then the 1:1 importer→`Cluster` mapping is the simpler shape.

- **Kubeconfig watcher** (`internal/k8shelpers`, `k8shelpers.KubeConfigWatcher` — a self-contained, reusable building block in its own package, but the cluster service owns the *instance*: `cluster.New` constructs it from `kubeconfigPath` and `Service.Start`/`Close` drive its `Start`/`Close`) — fsnotify + 100ms debounce over the kubeconfig precedence paths, publishing full `*api.Config` snapshots on a latest-value hub (current-on-subscribe). The importer and `ClusterController` consume it through the package-local `KubeConfigSource` interface (`Get`/`Subscribe`; tests substitute a static fake): the importer consumes the snapshot stream, the controller only reads `Get()` for credential resolution.
- **Domain types** (`types.go`, `helpers.go`) — `Cluster{ID, Generation, CreatedAt, ArchivedAt, DeletedAt, Spec, Status}`, keyed by a UUID `ClusterID` (deliberately not the remote cluster's UID). `ClusterSpec` is user/API-owned (`Name`, `IsSyncEnabled`, `IsActive`, `Source` — a discriminated union `ClusterSource{Kubeconfig *ClusterSourceKubeconfig{Context}}`, Manual/Cloud later), plus two internal trigger fields (`RetryGeneration`, `PokeSyncGeneration`) and `SourceObs` (the kubeconfig observation the **importer** writes into the spec, which `ClusterController` mirrors into status — a spec field because only a kind's own controller may write its status). The beehive **stored** types are `ClusterConnectionStatus` (Cluster kind: `Source`/`Server`/`Principal`/`LastConnectedAt` + `Connected`/`Healthy` conditions) and `ClusterCacheStatus` (ClusterCache kind: the `Synced` condition + `LastSyncedAt` + `ObservedPokeSyncGeneration`). `Cluster.Status` (`ClusterStatus`) is the assembled domain view the service builds by joining the two. `ClusterCondition` is k8s-style `{Type, Status, Reason, Message, ObservedGeneration, LastTransitionTime}`, folded via `SetCondition` (apimachinery `SetStatusCondition` semantics). gqlgen binds the GraphQL `Cluster` straight to these types.
- **ClusterController** (`core_controller.go`) — the connection/health controller. Each reconcile: eligibility gate (`ConnectionEligible`: kubeconfig-sourced, present, active, not deletion-requested) → resolve credentials → identity probe (ServerVersion, kube-system UID, SelfSubjectReview) → `/readyz` health check, folding observations into the `Connected`/`Healthy` conditions and refreshing `Server`/`Principal`/`LastConnectedAt` on success. A probe failure is an observation, not an error — it requests a doubling-backoff requeue (1s→2m via beehive's per-key `RetryAfter`); success requests the ~30s health cadence. `probe`/`check` default to the real network implementations; tests inject fakes. It also ensures a `ClusterCache` child exists. `RetryGeneration` (bumped by `Service.RetryConnection`) forces an immediate re-probe.
- **ClusterCacheController** (`cache_controller.go`) — the cache-sync controller: converges a runtime map of **running engines** toward each record's spec. It adds a `DependsOn` edge to the parent Cluster (so a `PokeSyncGeneration` bump re-queues it), gates on `syncEligible` (`ConnectionEligible && IsSyncEnabled`), resolves credentials, computes `engine.ConfigFingerprint`, and starts/stops/restarts the engine — restart on fingerprint change (credential rotation) or a poke bounce. Sync is deliberately **not** gated on `Connected` (the engine owns its own dial/backoff). Engine outcomes land through a per-engine sink, folding `Syncing`/`Watching`/`Errored` into the `Synced` condition.
- **Kubeconfig importer** (`kubeconfig_importer.go`) — the kubeconfig-sourced creator and **sole creator of `Cluster` objects**: consumes watcher snapshots and diffs each against the existing kubeconfig-sourced `Cluster` objects (indexed by `Spec.Source.Kubeconfig.Context`). New context → create a `Cluster` (minting a UUID, seeding `SourceObs`); changed observation → update `SourceObs`; departed context → orphan (`SourceObs.IsPresent=false`, **never** a deletion); returning context → revive in place (same object). An unchanged snapshot writes nothing. A pure beehive writer — it doesn't know `ClusterController` exists; its `Start`/`Stop` are owned by `Service`. (It absorbed the old `ClusterSourceController`'s UUID-minting + child-creation when the intake kind was collapsed.)
- **Per-cluster cache** (`internal/cluster/cache/store`) — one SQLite file per record at `<dataDir>/clusters/<ClusterID>.db` (pure-Go modernc driver, WAL; single-conn writer pool + 4-conn reader pool), owned by a `Manager` (`Open`/`Lookup`/`CacheBytes` (stat-only, works closed)/`ResourceStats`/`DeleteCacheFiles`/`Shutdown`). Open runs an integrity check (corrupt → quarantined as `.corrupt-<stamp>`), migrations (its own embedded sequence — agent-optimized schema: universal `objects` + `owner_refs`/`labels`/`status_history`/`events`(+FTS)/`kind_catalog`/`cluster_meta`; `raw_json` zlib-compressed, Secrets redacted before persist), and a per-cluster janitor (event TTL sweeps + incremental vacuum). The cache never owns syncing — engines are the cache controller's.
- **Sync engine** (`internal/cluster/cache/engine`) — mirrors one cluster into its cache for as long as it runs; the cache controller starts/stops it (`NewEngine(restCfg, cdb, sink)`/`Start`/`Stop`). A supervised run walks `/apis` discovery and drives one `kindDriver` per GVR — built instead of a raw Reflector so a wake resumes cheaply: it seeds a RetryWatcher from the kind's persisted resourceVersion (`cluster_meta` resume cookie) and only on a 410/cold cache falls back to a metadata-first re-sync. The engine reports coarse state through its `Sink` (`Syncing` → `Watching` → `Errored` + capped retry). `ConfigFingerprint` hashes a rest.Config's connection/auth fields (+ kubeconfig proxy-url) — the controller's restart trigger.

The GraphQL `Cluster` mirrors the spec/status split (the schema **is** the domain shape — see gqlgen.yml's Cluster bindings, all pointing at `internal/cluster` types): `spec`/`status` bind to `cluster.ClusterSpec`/the assembled record (`ClusterSource`/`ClusterSourceKubeconfig` bind directly, so the source union is on the wire as nested nullable objects), with `status` going through a thin hand-written `model.ClusterStatus` wrapper (`graph/model/models.go`) — an embedded `cluster.ClusterStatus` plus the `ClusterID` — because the `cache` child resolver (a resolver so a query only pays for what it selects) needs the cluster's ID and a child resolver only sees its own obj. **The conditions go on the wire as-is**: `status.conditions` and `status.syncStatus { conditions, lastSyncedAt }` bind straight to `cluster.ClusterCondition`/`cluster.ClusterCacheStatus`, and the webview derives display state from type/status/reason — there is no projection layer. `ClusterCache`/`CachedResource` bind to `cluster.CacheStats`/`cluster.CachedResourceStats`. **Every cluster resolver delegates to `r.ClusterSvc` (`cluster.ClusterService`)** — they are one-liners: `clusters`/`cluster(id)` → `List()`/`Get()`; `clustersWatch` → `Watch()` (emits the current list on subscribe, then re-emits the full list on every Cluster or ClusterCache change); `cache` → `CacheStats()`; `clusterSyncEnabledSet` → `SetSyncEnabled`; `clusterConnectionRetry` → `RetryConnection` (returns immediately; the outcome lands on conditions and reaches the webview through the cluster watch); `clusterCacheClear` → `ClearCache` (delete cache files + bump `PokeSyncGeneration`); `clusterDelete` → `Delete` (delete the `Cluster` so GC cascades to `ClusterCache`; if the kube-context still exists the importer re-creates it with a fresh UUID). The resolver field is named `ClusterSvc` (not `Clusters`) to avoid shadowing the generated `queryResolver.Clusters` method. The frontend `cluster-sync-panel.tsx` renders `clustersWatch` as a grouped Active/Orphaned table keyed on `status.source.kubeconfig?.isPresent`, with a "pending" row state derived from `status.server.uid == null`.

The data dir (`--data-dir` / env `KSTACK_DATA_DIR`) is **required** — `app.New` errors when it's empty; the Tauri host wires its `app_local_data_dir()`, tests supply `t.TempDir()`. `<data-dir>/app.db` is **owned by `internal/appdb`**, which opens it, holds its one migration sequence, and hands the `*sql.DB` to feature packages (a SQLite file has a single `schema_migrations` sequence, so its schema can't be co-owned; add a new app-level table as a numbered migration in `appdb/migrations/`, not as a second embed against the same file).

## Auth / identity (`internal/auth`) — the local-first lower layer

User accounts backed by kstack-cloud's Hydra OAuth server (`https://oauth.kstack.sh/`). The whole flow is **sidecar-owned**: the sidecar opens the system browser (auth-code + PKCE, ephemeral loopback redirect), runs the loopback listener, exchanges + verifies the code, **and persists the refresh token in the OS keyring itself** (via an internal `keyringStore` over `zalando/go-keyring` — loopback OAuth already pins the browser to this machine, so there's no host round-trip and **no gRPC credentials channel**). This is **local-first**: a user stays signed in offline — identity is read back from a locally-stored ID token, and a present refresh token is what marks "signed in." It's deliberately **independent of the cloud settings feature**: the settings-sync subsystem (`internal/cloud`) depends on `auth` (for an `oauth2.TokenSource` and the latest-value session `State` stream), **not the reverse**. Like `cluster`/`cloud`, it's fronted by one composition owner and **degrades** when neither a keychain service name nor a credentials store is configured (signed-out, login errors, logout is a no-op, `TokenSource()` nil). The composition root (`internal/app`) configures auth by name, not by wiring (`main.go` passes `OAuthIssuerURL`/`OAuthClientID` — from `KSTACK_OAUTH_ISSUER`/`KSTACK_OAUTH_CLIENT_ID` — plus the keychain service name to `app.Config`, which hands them to `auth.New` as `Config.IssuerURL`/`ClientID`/`KeychainService`. `auth.New` then builds its **own** dependencies: it derives Hydra's standard endpoint paths from the issuer via `newHydraOAuthConfig` (a caller-side helper in `auth.go`; the `auth/oauth` sub-package stays Hydra-agnostic, taking resolved endpoint URLs), and builds its own `keyringStore` over the service name — so only the issuer, client id, and keychain name are configured, no constructed store/config is passed in. `Config` carries **only production knobs** (`IssuerURL`/`ClientID`/`Scopes`/`KeychainService`) — nothing on it lets a caller bypass the real OAuth flow, and `New(Config)` takes no other arguments. The test seams are **unexported functional options** applied by an unexported `newWithOptions(cfg, opts...)` builder that `New` wraps (`withOAuthConfig` → httptest endpoints, `withCredentialsStore` → in-memory store, `withOAuthFlow`/`withLoopback`/`withBrowserOpener` → fakes); they resolve at construction (they pick the store/oauth client the grant is built over) and are reachable only from `auth`'s own (white-box) tests. Auth degrades to signed-out when neither a keychain name nor a `withCredentialsStore` option is given.) It threads the `auth.Service` into the `graph.Resolver` as one `Auth` field — always non-nil; the service itself degrades (signed-out, erroring login) when unconfigured — backing the `authState` query, `authLoginStart`/`authLogout` mutations, and `authStateWatch` subscription (built/consumed by the webview's `src/lib/auth.tsx`).

**Mostly flat, one carved-out sub-package.** The root `package auth` is deliberately flat (no `session`/`credentials` sub-packages — those files share a dense web of value types and would only have to export private state-machine internals to live apart). It's organized **by domain into four files**: `auth.go` (the service facade — the public `Service` interface, the `State`/`TokenSet` value types, the `Token`/`Identity` aliases, `Config` + the test options, and the composition owner; named to match the `cluster.go`/`cloud.go` convention), `grant.go` (the **grant aggregate** plus everything it owns — the credential state machine, its `CredentialsStore`/`RefreshFunc` ports + `ErrSignedOut` defined consumer-side, and the `grantTokenSource` `oauth2.TokenSource` adapter), `login.go` (the **interactive login flow** — the unexported `loginFlow` that runs loopback → browser → exchange → verify, the PKCE verifier/state generation + browser opener that feed it, the flow's seam interfaces `OAuthFlow`/`Loopback`/`LoopbackFunc` and the `loginStarter`/`pendingLogin` types the service holds the login step behind, **and the 127.0.0.1 `loopbackServer` redirect listener** that implements the flow's own `Loopback` seam — `(*loginFlow).start` runs the **synchronous setup** (loopback bind + browser open) and returns a `pendingLogin` for the slow async tail), and `keyring.go` (the OS-keyring credential persistence — the unexported `keyringStore`, the lone concrete `CredentialsStore` impl, kept apart from the aggregate since it carries its own `zalando/go-keyring` dependency).

The **one** piece carved out is `internal/auth/oauth` (`package oauth`) — the OAuth2/OIDC **protocol layer**, the subsystem's one genuine deep module (PKCE S256, JWKS verification via go-oidc, RFC 7009 revocation, token exchange/refresh) behind a small `Client` surface. It is a **leaf**: `auth` builds an `oauth.Client` (via `oauth.NewClient(oauth.Config)`) and drives it, so `oauth` must not import `auth`. Because `oauth.Client` *produces* the `Token` and `Identity` value types, those types **live in `oauth`** (avoiding the import cycle that keeping them in root would force), and `auth.go` re-exports them as true type aliases (`type Token = oauth.Token`, `type Identity = oauth.Identity`) so the rest of `auth` and external consumers (`graph`, `cloud`) keep naming them `auth.Token`/`auth.Identity` with no conversion and no sub-package import. `oauth.ParseIdentityUnverified` (display-only claim decode, used by the grant on cache restore) is the one other exported helper `auth` calls across the boundary.

The grant aggregate, the loopback listener, the login flow, and the keyring store remain **unexported** (`grant`/`loopbackServer`/`loginFlow`/`keyringStore`); the root's exported surface is the `Service` interface, its `New(Config)` constructor (with an unexported `newWithOptions(cfg, opts...)` builder that white-box tests use to inject `option` seams), the seam interfaces (`OAuthFlow`/`Loopback`/`LoopbackFunc`), the `Token`/`Identity` aliases, and the persistence types. External consumers (`graph`, `cloud`) that need a stand-in fake the `Service` interface directly rather than constructing a real service with seams.

- **`Service`** is an **interface** (`auth.New(Config) (Service, error)`), passed around to consumers like the cloud client. It owns **no long-lived goroutines, so there's no `Start`/`Close`** (restore happens in `newGrant`; revocation is a per-`Logout` fire-and-forget, and `StartLogin`'s async tail is likewise bounded fire-and-forget — see below). Methods: `Current(ctx) (State, error)` (the current `State` — `Authenticated` + `Identity` + `TokenSet`, no forced refresh), `StartLogin(ctx)` (runs the `loginFlow`'s **synchronous setup** — loopback bind + browser open — under the caller's ctx and **returns its error synchronously** so the `login` mutation can surface a setup failure to the UI; the slow tail — wait for redirect → exchange → `Verify` → `grant.set(tok, identity)`, which persists before publishing the signed-in `State` — then runs in a **bounded, detached fire-and-forget goroutine** (`loginTimeout`, not tied to shutdown — like `Logout`'s revoke), its completion observed via `Subscribe`/`authStateWatch`; a tail failure is logged and stays signed-out. The flow's two phases are tested directly in `login_test.go`, while a service-level test fakes the whole login step via the `withLoginStarter` option — so the per-part flow seams don't leak onto the service's build path), `Logout(ctx)` (captures the refresh token, `grant.clear()`s local-first — publishes the signed-out `State` — then `Revoke`s fire-and-forget on its own bounded context; if the keychain write fails it returns the error and stays signed in), `TokenSource(ctx) oauth2.TokenSource` (a `grantTokenSource` adapter capturing `ctx` for the lazy refresh exchange; **nil when degraded**), and `Subscribe() (<-chan State, func())` (a **latest-value** session-state stream — current-on-subscribe, then each change — plus cancel).

**The grant aggregate models the OAuth grant.** The unexported `grant` aggregate owns the **token set as the source of truth** plus the cached identity; `State.Authenticated` and `State.Identity` are **derived** (signed-in ⇔ a refresh token is present), never stored alongside, so credential state and the published `State` can't drift (the dual-write that `TestLogoutKeepsSessionWhenCredentialClearFails` guards is gone). It owns the token (cache + **lazy refresh**, mutex serializing a burst into a single refresh, persist-before-cache) and a `gochan/watch` hub publishing the **current session `State`** (latest-value, current-on-subscribe; seeded with the restored State at construction). A sign-in/out republishes a flipped `Authenticated`; a routine refresh republishes the same `Authenticated` bit with a renewed `Tokens` projection — so a consumer that keys off the sign-in bit sees no transition on refresh, without any event-type tagging. `newGrant(store, refresh, opts)` restores from the store (decode identity via `parseIdentityUnverified` — display-only; the cloud re-verifies the access token per request). `validToken`/`current`/`set`/`clear`/`state`/`subscribe` are the internal ports. **Refresh decision:** the cache/refresh/dedup is hand-rolled (we keep per-call `ctx` into refresh, which a long-lived `oauth2.ReuseTokenSource` would bake in at construction); only the refresh *HTTP exchange* is delegated to `golang.org/x/oauth2` inside the oauth client's `Refresh`.

**Token-source shape & leak posture.** Downstream consumers get an **`oauth2.TokenSource`** (the cloud api client builds one per request from the request `ctx` via `Service.TokenSource`, so the bounded token-fetch timeout governs each refresh). This is the idiomatic shape but **does expose the refresh token** on the returned `*oauth2.Token` — the old string-only `credentials.TokenSource` compile-time leak guarantee is gone; the api client simply reads `AccessToken` and never inspects the rest. The resolver still maps only the tokenless projection (`State.Authenticated` + `State.Identity` → `AuthState { authenticated, identity }`); `State.Tokens` (a `TokenSet`) rides along for in-process callers but is dropped by the GraphQL projection.

**Hydra OIDC mechanics** (the `auth/oauth` sub-package, plus the loopback listener in `login.go`): PKCE (`generateVerifier` in `login.go` / `s256Challenge` in `oauth`), `Client.AuthCodeURL`, a 127.0.0.1 `loopbackServer` redirect listener (in `login.go`, behind the exported `Loopback` seam), `Client.Exchange`/`Refresh` (via `golang.org/x/oauth2`), `Client.Revoke` (RFC 7009 token revocation — public client, posts `token`+`client_id` to `oauth.Config.RevocationURL`; revoking the refresh token also kills the grant's access tokens), and `Client.Verify` (ID-token signature/iss/aud/exp via `github.com/coreos/go-oidc/v3` against Hydra's JWKS) → `Identity{UserID,Email,Name}` (claim `sub` → `UserID`). **Identity comes from the verified ID token**, so no extra profile round-trip.

## Cloud settings sync (`internal/cloud`) — depends on `auth`

Cloud-synced settings (later AI-model routing) backed by kstack-cloud's API. Settings are **local-first**: an edit applies to a local JSON file immediately and is queued for the cloud, surviving offline/restart. The subsystem **depends on `internal/auth`** — it authenticates the api client from `authSvc.TokenSource`, and **wakes its sync engine by observing `authSvc.Subscribe()` session `State`** (the inverse of the old auth→engine poke: `auth` knows nothing about the engine). It **degrades** when unconfigured (no cloud URL / data dir ⇒ no settings sync). The composition root (`internal/app`) wires CloudURL (`KSTACK_CLOUD_URL`) and hands the `auth.Service` to `cloud.New(dataDir, cloudURL, authSvc)`.

- `internal/cloud` (root package `cloud`) — **composition + lifecycle owner**, mirroring `cluster.Service`. `cloud.New(dataDir, cloudURL string, authSvc auth.Service)` wires prefs + queue + engine, building the api upstream from `authSvc.TokenSource` (degraded — no engine — without a data dir, or without a cloud URL + a non-nil token source). `Start(ctx)` runs the settings-sync engine (idempotent — a second `Start` is a no-op so it can't leak an engine goroutine) **plus a goroutine that observes the auth session `State` and pokes the engine only when `Authenticated` flips** (sign-in → authenticate + sync now; sign-out → cancel the in-flight authenticated watch). The stream is latest-value (current-on-subscribe), so the goroutine seeds its baseline from the first `State` without poking, and a routine token refresh — which leaves `Authenticated` unchanged — never wakes the engine. Tracking the single `Authenticated` bit (not the whole `State`) is what makes refresh a non-event, so the old "poke on any state ≠ the last seen" dance (which compared the whole state, incl. tokens, and so fired on refresh) stays gone. `Close()` stops the engine **and** the poke goroutine. Exposes `Prefs()` (the settings store, nil when degraded). The required production inputs are positional constructor args (`dataDir`, `cloudURL`), not a config struct; the test seam (a fake sync upstream instead of the api client) is an **unexported functional option** — `withUpstream`, applied by an unexported `newWithOptions(dataDir, cloudURL, authSvc, opts...)` builder that `New` wraps and reachable only from `cloud`'s own (white-box) tests, mirroring the `auth` subsystem's option pattern.

Sub-packages (each TDD'd in isolation, leaf-first):

- `internal/cloud/syncstore` — generic `Envelope[T]{Data, Version, LastSyncedAt, LastEventAt}` + `Store[T]` over `internal/atomicjson` (crash-safe JSON; serialized writers). The reconcile-state file primitive.
- `internal/cloud/prefs` — the `Settings` type (**pointer fields + omitempty** so absent ≠ cleared, for the cloud's deep-merge), `Merge(base, patch)` (the local-first reconcile primitive), `Clone` (deep copy), and `Store` (persist + a `gochan/watch` hub that publishes current-on-subscribe, with an equality guard so an unchanged `Set` neither writes disk nor publishes). Because `Settings` holds pointers, the `Store` (Set/Get) and the `mutationqueue` (Enqueue/Pending) **deep-copy at their boundaries** so a caller mutating a string it passed in (or one it got back) can't desync in-memory state from the persisted JSON or queued payload.
- `internal/cloud/mutationqueue` — durable FIFO of pending local patches (atomicjson-backed, monotonic non-random ids). `Enqueue`/`Pending`/`Ack`; survives restart so offline edits still reach the cloud.
- `internal/cloud/api` — minimal GraphQL-over-HTTP cloud client (POST + SSE `WatchSettings`), authenticating every request from a per-request `oauth2.TokenSource` built from a `func(context.Context) oauth2.TokenSource` factory (`auth.Service.TokenSource`), reading its `AccessToken` — not a per-call token threaded through.
- `internal/cloud/prefsync` — the always-on reconcile `Engine` + `Upstream` interface (`Snapshot`/`Watch`/`Update`). `Watch` returns the settings channel **plus a buffered terminal-error channel** (nil = clean end / ctx cancel; non-nil = a read/transport failure **or** a GraphQL subscription error frame, which ends the stream rather than being silently skipped) so the engine distinguishes an errored close (record `LastError`, keep escalating backoff) from a healthy one — a nil error channel is treated as a clean end. Supervised connection with exponential backoff + poke. Production builds with `New(up, store, queue, notifier)` (defaults only); the deterministic `Now`/`Sleep`/`Jitter`/backoff seams are **unexported functional options** (`withNow`/`withSleep`/`withJitter`/`withBackoff`) applied by an unexported `newWithOptions(..., opts ...option)` builder that `New` wraps — reachable only from the package's white-box tests, mirroring the `auth`/`cloud` option pattern (so prefsync's tests are `package prefsync`, not `_test`). Wake/resync signals arrive via the `*poke.Service` passed to `New` (the shared broadcaster) — a wired-in dependency alongside `up`/`store`/`queue`, *not* a tunable option; nil disables external wake signals (tests, degraded runs). It's the concrete type, not an interface: `prefsync` already imports `poke` (the signals are `poke.Signal`), so an interface would decouple nothing — `poke` stays a leaf because it never imports `prefsync`, interface or not. `Set` is **local-first** (write store + enqueue + poke); on Live it **drains the queue** via `Upstream.Update` and acks; incoming snapshots/events have **still-pending patches re-layered on top** (`prefs.Merge`) so a stale cloud snapshot can't clobber an unacked local edit.

## Resync broadcaster (`internal/poke`)

`internal/poke` is a **cross-subsystem, leaf package** — no imports from other `internal/` packages. It owns two jobs:

1. **Wall-clock gap detector**: runs a ticker and compares the elapsed wall-clock time against the expected interval (default 15s tick, 2× gap factor). A jump larger than the threshold means the process was frozen (machine sleep, SIGSTOP, VM pause) — it fires a `Poke(SourceWallClock)`. This is the backstop that needs no OS event and works headless.
2. **Fan-out broadcaster**: every poke (from the detector or a direct `Poke(SourceHost)` call) is broadcast to all current subscribers via a `github.com/amorey/gochan/broadcast` hub. The `SourceHost` entry point is driven by the host gRPC `PokeService.Poke` handler (`grpc/poke_server.go`) — the host calls it on OS resume / network-on. (The Rust host trigger that actually calls the RPC is a separate `src-tauri/` change.)

**API**: `New()` → `*Service` (no arguments — production tunes nothing); `Start(ctx)`/`Close()` (the composition-root lifecycle pair, mirroring `cluster.Service`/`cloud.Service` — `Start` runs the detector in a goroutine, `Close` cancels and waits, closing the hub) or the lower-level `Run(ctx)` it wraps (blocks, used directly by tests); `Poke(src)` (never blocks, safe from any goroutine); `Subscribe()` (returns `(<-chan Signal, func())`). `internal/app` owns the one `*poke.Service`'s lifecycle and hands it to `cluster.New`, `cloud.New`, and `grpcserver.NewServer`. The integrations sharing the one broadcaster: the settings engine receives signals via the `*poke.Service` it's given in `prefsync.New`; the host gRPC `PokeService` produces `SourceHost` pokes; the cluster service's poke→sync forwarder (in `cluster.Service.Start`) bumps `PokeSyncGeneration` on every Cluster, which the `ClusterCacheController` observes (via its `DependsOn` edge) to bounce running sync engines — they restart and resume cheaply from their persisted resourceVersions.

Test seams: the gap-detector tuning (`tick`/`gapFactor`) and the clock/ticker (`now`/`newTicker`) are **unexported functional options** (`withTick`/`withGapFactor`/`withNow`/`withTicker`) applied by an unexported `newWithOptions(opts ...option)` builder that `New` wraps — reachable only from poke's own white-box tests, mirroring the `auth`/`cloud`/`prefsync` option pattern. Production never tunes them (the gap detector's defaults are fixed and the gRPC `PokeService` only calls `Poke`, never reconfigures the detector), so `New` exposes no knobs; the external consumers that hold a `*poke.Service` in tests just call `New()` and drive `Poke` directly.

## gRPC + GraphQL over one socket (h2c)

gRPC needs HTTP/2; GraphQL stays HTTP/1.1. `internal/app` wraps the GraphQL/control mux in `h2c.NewHandler` whose dispatcher routes requests matching `grpcserver.IsGRPCRequest` to the `*grpc.Server` and everything else to the mux. The predicate lives in `grpc/` because it *is* the definition of a gRPC request (HTTP/2 *and* `application/grpc`); the composition root owns the dispatch + h2c wiring (the decision that these two surfaces share one socket). Each concern stays with its owner without a separate multiplexer package — `grpc/` owns "what is a gRPC request", `app` owns the topology. HTTP/1.1 GraphQL POST + SSE are untouched (they keep `ProtoMajor==1` and a Flusher-backed writer). An idle `AuthStateWatch` stream is kept alive under the server's 60s `IdleTimeout` by a gRPC keepalive ping. The webview uses GraphQL; the host (tray) uses gRPC (auth-state watch + login/logout, resync poke). The cluster surface is GraphQL-only (`clusters`/`clustersWatch` + cluster mutations).

**Shutdown** is driven through the `App` surface from `main.go`. `srv.RegisterOnShutdown(app.NotifyShutdown)` fires the moment `srv.Shutdown` begins, then:

1. **`app.NotifyShutdown()`** fans out to both sub-servers: `grpcServer.NotifyShutdown()` cancels the serving context (every `Watch` handler returns `nil` → grpc writes its OK trailers → each client sees a clean `io.EOF`), and `graphqlServer.NotifyShutdown()` closes a `shutdownCh` that cancels each active SSE subscription's request context (gqlgen flushes its terminal `event: complete`).
2. **`srv.Shutdown(ctx)`** stops accepting and waits for the non-hijacked GraphQL requests to finish — the SSE streams, now cancelled, flush and return.
3. **`app.DrainWithContext(ctx)`** waits on *both* sub-servers' `WaitGroup`s. This is the essential wait for the **hijacked h2c gRPC streams** that `srv.Shutdown` does not track; for GraphQL it's belt-and-suspenders.
4. **`app.Close()`** stops the gRPC transports (`grpcServer.Stop()`) and tears down the services — closes the poke broadcaster + watcher, then `clusterSvc.Close()` (which owns the whole cluster control-plane teardown order: stop writers → stop beehive's controllers + engines → shut the per-cluster cache → close the beehive store) and cloud.

Why it's built this way (the non-obvious parts): grpc's own `GracefulStop` **panics** on the `ServeHTTP`/h2c path, so the stream must end on its own serving context instead, and `Stop` only runs in step 4 after the streams have drained. The GraphQL SSE drain is **per-request** (`graph.Server.ServeHTTP` wires each SSE request's context to `shutdownCh`), deliberately **not** via `http.Server.BaseContext`: a `BaseContext` cancel would tear down the shared h2c connection carrying gRPC mid-stream. Because nothing touches `BaseContext`, the two transports are independent — `NotifyShutdown` signals both at once and there is no required gRPC-before-GraphQL ordering. (The h2c dispatcher also routes gRPC away *before* the GraphQL server's `ServeHTTP`, so a long-lived gRPC connection is never counted in the GraphQL `WaitGroup`.)

## Patterns

- **Resolver deps are always non-nil**: the composition root (`internal/app`) wires every `Resolver` field, and resolvers call their deps without nil guards — degraded behavior (e.g. no cloud account) lives inside the services themselves (`auth.New` degrades internally; the data dir is simply required). Tests construct the `Resolver` with fakes (e.g. `newFakeAuth`) rather than relying on nil tolerance.
- **Pub/sub**: `github.com/amorey/gochan` hubs fan snapshots to subscribers — `watch` for latest-value "current state" streams (the kubeconfig watcher and the auth session-`State` stream, both delivering the current snapshot on subscribe — a consumer needs no separate "read current" call to seed itself), `broadcast` for fan-out streams whose subscribers supply their own initial snapshot (the `poke` resync broadcaster). Watchers use fsnotify + a debounce, then publish the new snapshot.
- **Subscription resolvers**: return a channel that **emits the current snapshot first, then deltas**. Hub-backed sources forward through `mapStream` (`graph/util.go` — the source is current-on-subscribe, so its first value IS the snapshot; see `authStateWatch`). `clustersWatch` is the interim exception: one snapshot, then the channel is held open until ctx ends (no hub behind it yet). Honor `ctx.Done()`.

## Tests & checks

- testify + `net/http/httptest`. Resolver-level GraphQL tests stand up `graph.NewServer(&graph.Resolver{...})` and `POST /graphql` (in `graph/`); h2c/control/lifecycle tests stand up `app.New(...)` (in `internal/app/`). Filesystem via `t.TempDir()` / `os.MkdirTemp`.
- **White-box tests by default** — a package's tests live in the same `package foo` (not `package foo_test`), so they can exercise unexported helpers directly with no export-tax. This mirrors the flat-package philosophy elsewhere in the tree (e.g. `internal/auth`): boundaries inside a package are kept by discipline + file ownership, not by the compiler, and the test layer follows the same rule. **Escape hatch:** reach for an external `package foo_test` only when a test's *purpose* is to pin the public contract and you want the compiler to *guarantee* it touches only the exported surface — then say so in a comment. Don't mix the two styles within one package without that reason.
- **Avoid magic sleeps.** Don't `time.Sleep` to wait for async work (fsnotify reloads, hub publishes) — block on the actual event with `<-sub.Chan()` guarded by a `select { case … : case <-time.After(deadline): t.Fatal(…) }` timeout, as the watcher tests do. A `time.After` deadline is fine; a fixed sleep is flaky and slow.
- `make test-go` (`cd sidecar && go test ./...`).
- `make lint-go` (gofmt) and `make vet-go` (`go vet`). Run `gofmt -w` before committing.

When you change the sidecar's schema workflow, wiring, or conventions, update this `CLAUDE.md` in the same change.
