# sidecar — Go backend

A standalone Go binary started by the Tauri host. It exposes the app's GraphQL API (and a gRPC control channel) and owns all Kubernetes logic. **No TCP** — it listens on a Unix domain socket (named pipe on Windows), prints `READY unix:<path>` to stdout so the host can dial it, and shuts down on `SIGINT`/`SIGTERM` or **stdin EOF** (the host closing its end = "parent gone").

## Layout

The codebase mirrors the **kubetail layout**: `main.go` is lifecycle only, `internal/app` is the composition root + routing, and the GraphQL server lives in `graph` (alongside the resolvers). There is **no `server` package**; "the server" is the thin listener in `main.go`.

- `main.go` — **lifecycle only**. Parses flags, binds the socket, builds the `*app.App`, mounts it on an `http.Server`, registers `app.NotifyShutdown` via `srv.RegisterOnShutdown`, serves, and drives graceful shutdown (`srv.Shutdown` → `app.DrainWithContext` → `app.Close`). No composition logic.
- `internal/app/` — **composition root + routing + lifecycle owner**. `app.go` (`app.New(Config{...})`) builds the shared instances (the kube-config watcher and the cluster-cache `cluster.Service`), constructs the `graph.Resolver`, wires the GraphQL server (`graph.NewServer`) and gRPC server (`grpcserver.NewServer`), mounts them on a mux, and multiplexes onto one h2c handler: an `h2c.NewHandler` whose dispatcher sends `grpcserver.IsGRPCRequest` traffic to the gRPC server and everything else to the mux. It owns this *composition* — that these two surfaces share a socket and the h2c wiring itself — while `grpc/` owns the gRPC-request predicate. `App` is a thin `http.Handler`: it holds the two sub-servers, the watcher, and the cluster `*cluster.Service`, delegating `Start`/`Close` to the service and fanning `NotifyShutdown`/`DrainWithContext`/`Close` out to the sub-servers. `Close` tears the service down *before* the watcher (the service's coordinator is the watcher's only subscriber here).
- `graph/` — GraphQL: `schema.graphqls`, generated code, resolvers, and **`server.go`** — `graph.Server` (`NewServer(*Resolver)`), the gqlgen handler with the bearer-token plumbing, SSE shutdown lifecycle, and `NotifyShutdown`/`DrainWithContext` (see Shutdown below). A bare `&Resolver{}` is tolerated (nil `Sync` → Offline) so tests can stand up a minimal surface.
- `grpc/` — gRPC surface. `grpc/server.go`: `grpcserver.NewServer(watcher, authSvc)` wraps a `*grpc.Server` (registering both `KubeContextService` and `AuthService`, sharing the same `streams` WaitGroup so both drain together) with the `NotifyShutdown`/`DrainWithContext`/`Stop` lifecycle surface. `grpc/auth_server.go` implements `AuthService` over `auth.Service`: `StartLogin`/`Logout` (unary, nil-service → `Unavailable`) and `AuthStateWatch` (server-streaming, latest-value from `auth.Subscribe()`, nil-service → end immediately). `grpc/kubecontextpb/` holds the committed protoc output for `proto/kubecontext.proto`; `grpc/authpb/` holds the committed output for `proto/auth.proto`. Regenerate both with `make proto` (or `go generate ./grpc/...`); never hand-edit `*.pb.go`. The predicate `IsGRPCRequest` lives in `grpc/server.go`; the composition root uses it to route the shared h2c socket.
- `internal/` — building blocks: `app` (composition root, above), `ipc` (binds the per-OS IPC endpoint — AF_UNIX socket / named pipe — with user-only access; `main.go` uses `ipc.Listen`/`DefaultSocketPath`/`Scheme`), `k8shelpers` (kubeconfig watcher), `atomicjson` (crash-safe single-file JSON read/write), `logging`, `sqlitemigrate` (shared forward-only SQLite migration runner), `appdb` (owns the app-level `app.db` — its connection pool and single migration sequence — and hands the `*sql.DB` to consumers), plus the **cluster** packages under `internal/cluster/` (the root `cluster` package — `cluster.Service`, the composition + lifecycle owner — and the **cluster cache** sub-packages below), the **auth** packages under `internal/auth/` (the mostly-flat root `auth` package — `auth.Service`, the local-first identity layer — with the OAuth2/OIDC protocol layer carved into the `auth/oauth` sub-package), and the **cloud** packages under `internal/cloud/` (the root `cloud` package — `cloud.Service`, the cloud-synced settings feature that *depends on* `auth` — and its settings sub-packages; see *Auth / identity* and *Cloud settings sync* below).

## Cluster cache (per-cluster SQLite mirror)

A local SQLite mirror of every reachable Kubernetes cluster, so the GraphQL cluster-data surface answers from disk and never blocks on the live API, plus a durable registry of every cluster we've seen (so one survives in the UI after leaving the kubeconfig). Enabled only when the host passes `--data-dir` (env `KSTACK_DATA_DIR`) — the Tauri host wires its `app_local_data_dir()`; standalone/test runs omit it and the cluster resolvers degrade to empty results. Per-cluster DBs live at `<data-dir>/clusters/<cluster-uuid>.db` (UUID = the cluster's `kube-system` namespace UID, stable across context renames); the app-level `<data-dir>/app.db` (deliberately outside the `clusters/` dir, so the per-cluster cache scan doesn't mistake it for a `<uuid>.db` cache) holds the cluster registry — and is **owned by `internal/appdb`**, which opens it, holds its one migration sequence, and hands the `*sql.DB` to feature packages (a SQLite file has a single `schema_migrations` sequence, so its schema can't be co-owned; add a new app-level table as a numbered migration in `appdb/migrations/`, not as a second embed against the same file). The packages live under `internal/cluster/`, fronted by one composition owner:

- `internal/cluster` (root package `cluster`) — the subsystem's **composition + lifecycle owner**. `cluster.New(dataDir, watcher)` bundles the per-cluster cache, the registry (over `appdb`), and the coordinator — the three pieces enabled together only when a data dir is given — and exposes `Reader()` (cluster-data read side, always non-nil) + `Manager()` (the `clustersync.Manager` control surface, a nil interface with no data dir) for the resolver, plus `Start(ctx)`/`Close()` for `internal/app`. With an empty dataDir it degrades: nil cache/registry/coordinator, a Reader over a nil cache (empty snapshots), `Start`/`Close` no-op. `Close` orders the teardown (stop coordinator → drain cache → close app.db) in one place.

Four cluster-cache packages:

- `internal/clustercache` — storage + lifecycle. `Manager` owns one `ClusterDB` (WAL: 1 writer conn, 4 reader conns) per UUID; `Open`/`Close`/`Shutdown`/`Lookup`, plus cache-file ops `CacheBytes`/`DeleteCacheFiles`/`ScanCachedUUIDs` (all cover the `["", "-wal", "-shm"]` file group). (`Manager` is not a DB connection pool — each `ClusterDB` holds the real read/write `*sql.DB` pools; the `Manager` is the keyed set of those per-cluster DBs.) `ClusterDB.Subscribe()/Notify()` is the change-notifier the watch resolvers + the Coordinator's freshness tracker ride. Migrations under `migrations/*.sql` (embedded), applied by the shared `internal/sqlitemigrate` runner. `Open` starts the cluster's `Upstream.Run` sync goroutine per cluster plus a janitor (TTL sweep). Pure-Go driver (`modernc.org/sqlite`, no CGO).
- `internal/clusterregistry` — the **durable registry**. A small `clusters` table in the app-level `app.db` holding one `Record` per cluster: name, `Enabled`, and first-seen / last-synced / last-seen-in-kubeconfig timestamps. It is a **pure data-access layer**: `clusterregistry.New(*sql.DB)` takes the already-open, already-migrated handle from `internal/appdb` (it does not open or migrate the file, and must not close it); the table's schema lives in `appdb/migrations/`. SQLite is the source of truth, reads hit it directly. The Coordinator is the sole writer.
- `internal/clustersync` — the **write path** + the cluster manager. `Upstream.Run` discovers GVRs and drives one client-go `Reflector` per list/watchable resource (built-ins + CRDs) into the universal `objects` table (+ a dedicated `events` table). The `raw_json` column (the full object) is stored **zlib-compressed** via `clustercache.CompressRaw` (the largest column, ~4-5x; deterministic, self-identifying by its `0x78` header so no version prefix) — read it back through `clustercache.DecompressRaw`. `objects` is a *mirror*, not a log, so it's bounded without a TTL: each reflector deletes rows on watch-delete events and reconciles via a per-kind delete-missing prune on relist (`objectsStore.Replace`). The one gap that prune can't cover — a kind that vanishes entirely from discovery (e.g. an uninstalled CRD), since no reflector runs for it — is closed by `pruneOrphanedKinds`, which `discoverGVRs` runs after a **complete** discovery (skipped on partial discovery, so a transiently-unavailable API group isn't mistaken for a removed one) to evict `objects` rows whose `(kind, api_version)` is no longer discovered, cascade rows included. `Coordinator` keeps the registry, store and kubeconfig in lockstep: on every `KubeConfigWatcher` snapshot it `RecordSeen`s each reachable context (identified by `probeClusterUID`), opens clusters that are **present ∧ enabled**, freezes the rest, and backfills orphaned cache files on first run. It implements `clustersync.Manager` (the cluster read+control surface, held by the resolver as its `ClusterManager` field) — the merged `ClusterView` read surface (`Clusters`/`CurrentContext`/`Subscribe`) plus the `SetEnabled`/`DeleteCache` mutations (serialized with reconcile by an action-mutex). A per-open-cluster goroutine stamps freshness on each `Notify`, flushed to the store on a ~30s ticker. Discovery is live — a kubeconfig edit or a toggle reconciles without a restart. Kubeconfig **presence is name-based** (a context still in the kubeconfig stays present even when its UID probe transiently fails, so an outage doesn't orphan a live cluster); for an already-open cluster whose resolved `rest.Config` changes (rotated token/cert, new endpoint — detected via a config fingerprint) reconcile **restarts** that cluster's sync so reflectors pick up the new credentials. When two contexts resolve to one cluster UUID the current-context alias wins deterministically. The sync goroutine in `clustercache` **retries with backoff** if `Upstream.Run` returns while the cluster is still open. A kubeconfig context whose UID probe has **never** succeeded (a stopped/unreachable cluster, e.g. minikube not running) has no UUID and thus no registry record, so `buildViews` synthesizes a **pending** `ClusterView` for it — `Present` true, empty `UUID`, `Cached`/`Enabled` false — so it shows in the UI as a not-yet-synced Active row rather than vanishing; it's replaced by the real (identified, cached) row once a probe succeeds. Pending names skip those already covered by a registry record (a previously-probed context now unreachable keeps its own row) and probed aliases.
- `internal/clusterdata` — the **read path** for resource data. `Reader` turns `objects`/`events` rows into typed snapshots (`Pods/Services/Deployments/Nodes/Events`) + `Watch*` channels. It reads via `Registry.Lookup` (open-only-if-already-open), **never `Open`** — so a disabled (frozen) or absent cluster reads as empty and a read never starts a sync. All SQL lives here so `graph` stays a thin delegate-and-map shell; nil-tolerant.

The `graph` resolvers are one-line delegations: resource queries call `r.ClusterData.Pods(…)` etc.; `clusters`/`clustersWatch` map `ClusterManager.Clusters()` (`[]ClusterView`) → `model.*` via `graph/cluster_mappers.go` (using `streamWithSnapshot` for the subscription); `setClusterEnabled`/`deleteClusterCache`/`removeCluster` call `ClusterManager`. **`deleteClusterCache` (clear cache) vs `removeCluster` (forget) are distinct**: `DeleteCache` frees the on-disk cache files but **always keeps the registry row** (a present+enabled cluster re-syncs from scratch; otherwise the row stays, now uncached — including an orphan), while `RemoveCluster` deletes the cache files **and** drops the registry row entirely (meant for an orphan; a still-present context is re-discovered next reconcile). The composition root (`internal/app`) builds one `cluster.Service` (which owns the cache pool + registry + coordinator when `DataDir != ""`), threads its `Reader()` (always non-nil) and `Manager()` into the `Resolver`, and delegates `Start`/`Close` to it. (The frontend `cluster-sync-panel.tsx` renders `clustersWatch` as a grouped Active/Orphaned table and drives the three mutations from per-row action buttons; there is no separate per-cluster sync-status surface — status is derived from the `present`/`enabled`/`cached` flags, plus an empty `uuid` marking a still-unidentified "pending" context.)

## Auth / identity (`internal/auth`) — the local-first lower layer

User accounts backed by kstack-cloud's Hydra OAuth server (`https://oauth.kstack.sh/`). The whole flow is **sidecar-owned**: the sidecar opens the system browser (auth-code + PKCE, ephemeral loopback redirect), runs the loopback listener, exchanges + verifies the code, **and persists the refresh token in the OS keyring itself** (via an internal `keyringStore` over `zalando/go-keyring` — loopback OAuth already pins the browser to this machine, so there's no host round-trip and **no gRPC credentials channel**). This is **local-first**: a user stays signed in offline — identity is read back from a locally-stored ID token, and a present refresh token is what marks "signed in." It's deliberately **independent of the cloud settings feature**: the settings-sync subsystem (`internal/cloud`) depends on `auth` (for an `oauth2.TokenSource` and the latest-value session `State` stream), **not the reverse**. Like `cluster`/`cloud`, it's fronted by one composition owner and **degrades** when neither a keychain service name nor a credentials store is configured (signed-out, login errors, logout is a no-op, `TokenSource()` nil). The composition root (`internal/app`) configures auth by name, not by wiring (`main.go` passes `OAuthIssuerURL`/`OAuthClientID` — from `KSTACK_OAUTH_ISSUER`/`KSTACK_OAUTH_CLIENT_ID` — plus the keychain service name to `app.Config`, which hands them to `auth.New` as `Config.IssuerURL`/`ClientID`/`KeychainService`. `auth.New` then builds its **own** dependencies: it derives Hydra's standard endpoint paths from the issuer via `newHydraOAuthConfig` (a caller-side helper in `auth.go`; the `auth/oauth` sub-package stays Hydra-agnostic, taking resolved endpoint URLs), and builds its own `keyringStore` over the service name — so only the issuer, client id, and keychain name are configured, no constructed store/config is passed in. `Config` carries **only production knobs** (`IssuerURL`/`ClientID`/`Scopes`/`KeychainService`) — nothing on it lets a caller bypass the real OAuth flow, and `New(Config)` takes no other arguments. The test seams are **unexported functional options** applied by an unexported `newWithOptions(cfg, opts...)` builder that `New` wraps (`withOAuthConfig` → httptest endpoints, `withCredentialsStore` → in-memory store, `withOAuthFlow`/`withLoopback`/`withBrowserOpener` → fakes); they resolve at construction (they pick the store/oauth client the grant is built over) and are reachable only from `auth`'s own (white-box) tests. Auth degrades to signed-out when neither a keychain name nor a `withCredentialsStore` option is given.) It threads the `auth.Service` into the `graph.Resolver` as one `Auth` field — a single nil-check degrades the `authState` query, `login`/`logout` mutations, and `authStateWatch` subscription (built/consumed by the webview's `src/lib/auth.tsx`).

**Mostly flat, one carved-out sub-package.** The root `package auth` is deliberately flat (no `session`/`credentials` sub-packages — those files share a dense web of value types and would only have to export private state-machine internals to live apart). It's organized **by domain into four files**: `auth.go` (the service facade — the public `Service` interface, the `State`/`TokenSet` value types, the `Token`/`Identity` aliases, `Config` + the test options, and the composition owner; named to match the `cluster.go`/`cloud.go` convention), `grant.go` (the **grant aggregate** plus everything it owns — the credential state machine, its `CredentialsStore`/`RefreshFunc` ports + `ErrSignedOut` defined consumer-side, and the `grantTokenSource` `oauth2.TokenSource` adapter), `login.go` (the **interactive login flow** — the unexported `loginFlow` that runs loopback → browser → exchange → verify, the PKCE verifier/state generation + browser opener that feed it, the flow's seam interfaces `OAuthFlow`/`Loopback`/`LoopbackFunc` and the `loginStarter`/`pendingLogin` types the service holds the login step behind, **and the 127.0.0.1 `loopbackServer` redirect listener** that implements the flow's own `Loopback` seam — `(*loginFlow).start` runs the **synchronous setup** (loopback bind + browser open) and returns a `pendingLogin` for the slow async tail), and `keyring.go` (the OS-keyring credential persistence — the unexported `keyringStore`, the lone concrete `CredentialsStore` impl, kept apart from the aggregate since it carries its own `zalando/go-keyring` dependency).

The **one** piece carved out is `internal/auth/oauth` (`package oauth`) — the OAuth2/OIDC **protocol layer**, the subsystem's one genuine deep module (PKCE S256, JWKS verification via go-oidc, RFC 7009 revocation, token exchange/refresh) behind a small `Client` surface. It is a **leaf**: `auth` builds an `oauth.Client` (via `oauth.NewClient(oauth.Config)`) and drives it, so `oauth` must not import `auth`. Because `oauth.Client` *produces* the `Token` and `Identity` value types, those types **live in `oauth`** (avoiding the import cycle that keeping them in root would force), and `auth.go` re-exports them as true type aliases (`type Token = oauth.Token`, `type Identity = oauth.Identity`) so the rest of `auth` and external consumers (`graph`, `cloud`) keep naming them `auth.Token`/`auth.Identity` with no conversion and no sub-package import. `oauth.ParseIdentityUnverified` (display-only claim decode, used by the grant on cache restore) is the one other exported helper `auth` calls across the boundary.

The grant aggregate, the loopback listener, the login flow, and the keyring store remain **unexported** (`grant`/`loopbackServer`/`loginFlow`/`keyringStore`); the root's exported surface is the `Service` interface, its `New(Config)` constructor (with an unexported `newWithOptions(cfg, opts...)` builder that white-box tests use to inject `option` seams), the seam interfaces (`OAuthFlow`/`Loopback`/`LoopbackFunc`), the `Token`/`Identity` aliases, and the persistence types. External consumers (`graph`, `cloud`) that need a stand-in fake the `Service` interface directly rather than constructing a real service with seams.

- **`Service`** is an **interface** (`auth.New(Config) (Service, error)`), passed around to consumers like the cloud client. It owns **no long-lived goroutines, so there's no `Start`/`Close`** (restore happens in `newGrant`; revocation is a per-`Logout` fire-and-forget, and `StartLogin`'s async tail is likewise bounded fire-and-forget — see below). Methods: `Current(ctx) (State, error)` (the current `State` — `Authenticated` + `Identity` + `TokenSet`, no forced refresh), `StartLogin(ctx)` (runs the `loginFlow`'s **synchronous setup** — loopback bind + browser open — under the caller's ctx and **returns its error synchronously** so the `login` mutation can surface a setup failure to the UI; the slow tail — wait for redirect → exchange → `Verify` → `grant.set(tok, identity)`, which persists before publishing the signed-in `State` — then runs in a **bounded, detached fire-and-forget goroutine** (`loginTimeout`, not tied to shutdown — like `Logout`'s revoke), its completion observed via `Subscribe`/`authStateWatch`; a tail failure is logged and stays signed-out. The flow's two phases are tested directly in `login_test.go`, while a service-level test fakes the whole login step via the `withLoginStarter` option — so the per-part flow seams don't leak onto the service's build path), `Logout(ctx)` (captures the refresh token, `grant.clear()`s local-first — publishes the signed-out `State` — then `Revoke`s fire-and-forget on its own bounded context; if the keychain write fails it returns the error and stays signed in), `TokenSource(ctx) oauth2.TokenSource` (a `grantTokenSource` adapter capturing `ctx` for the lazy refresh exchange; **nil when degraded**), and `Subscribe() (<-chan State, func())` (a **latest-value** session-state stream — current-on-subscribe, then each change — plus cancel).

**The grant aggregate models the OAuth grant.** The unexported `grant` aggregate owns the **token set as the source of truth** plus the cached identity; `State.Authenticated` and `State.Identity` are **derived** (signed-in ⇔ a refresh token is present), never stored alongside, so credential state and the published `State` can't drift (the dual-write that `TestLogoutKeepsSessionWhenCredentialClearFails` guards is gone). It owns the token (cache + **lazy refresh**, mutex serializing a burst into a single refresh, persist-before-cache) and a `gochan/watch` hub publishing the **current session `State`** (latest-value, current-on-subscribe; seeded with the restored State at construction). A sign-in/out republishes a flipped `Authenticated`; a routine refresh republishes the same `Authenticated` bit with a renewed `Tokens` projection — so a consumer that keys off the sign-in bit sees no transition on refresh, without any event-type tagging. `newGrant(store, refresh, opts)` restores from the store (decode identity via `parseIdentityUnverified` — display-only; the cloud re-verifies the access token per request). `validToken`/`current`/`set`/`clear`/`state`/`subscribe` are the internal ports. **Refresh decision:** the cache/refresh/dedup is hand-rolled (we keep per-call `ctx` into refresh, which a long-lived `oauth2.ReuseTokenSource` would bake in at construction); only the refresh *HTTP exchange* is delegated to `golang.org/x/oauth2` inside the oauth client's `Refresh`.

**Token-source shape & leak posture.** Downstream consumers get an **`oauth2.TokenSource`** (the cloud api client builds one per request from the request `ctx` via `Service.TokenSource`, so the bounded token-fetch timeout governs each refresh). This is the idiomatic shape but **does expose the refresh token** on the returned `*oauth2.Token` — the old string-only `credentials.TokenSource` compile-time leak guarantee is gone; the api client simply reads `AccessToken` and never inspects the rest. The resolver still maps only the tokenless projection (`State.Authenticated` + `State.Identity` → `AuthState { authenticated, identity }`); `State.Tokens` (a `TokenSet`) rides along for in-process callers but is dropped by the GraphQL projection.

**Hydra OIDC mechanics** (the `auth/oauth` sub-package, plus the loopback listener in `login.go`): PKCE (`generateVerifier` in `login.go` / `s256Challenge` in `oauth`), `Client.AuthCodeURL`, a 127.0.0.1 `loopbackServer` redirect listener (in `login.go`, behind the exported `Loopback` seam), `Client.Exchange`/`Refresh` (via `golang.org/x/oauth2`), `Client.Revoke` (RFC 7009 token revocation — public client, posts `token`+`client_id` to `oauth.Config.RevocationURL`; revoking the refresh token also kills the grant's access tokens), and `Client.Verify` (ID-token signature/iss/aud/exp via `github.com/coreos/go-oidc/v3` against Hydra's JWKS) → `Identity{UserID,Email,Name}` (claim `sub` → `UserID`). **Identity comes from the verified ID token**, so no extra profile round-trip.

## Cloud settings sync (`internal/cloud`) — depends on `auth`

Cloud-synced settings (later AI-model routing) backed by kstack-cloud's API. Settings are **local-first**: an edit applies to a local JSON file immediately and is queued for the cloud, surviving offline/restart. The subsystem **depends on `internal/auth`** — it authenticates the api client from `authSvc.TokenSource`, and **wakes its sync engine by observing `authSvc.Subscribe()` session `State`** (the inverse of the old auth→engine poke: `auth` knows nothing about the engine). It **degrades** when unconfigured (no cloud URL / data dir ⇒ no settings sync). The composition root (`internal/app`) wires CloudURL (`KSTACK_CLOUD_URL`) and hands the `auth.Service` to `cloud.New(dataDir, cloudURL, authSvc)`.

- `internal/cloud` (root package `cloud`) — **composition + lifecycle owner**, mirroring `cluster.Service`. `cloud.New(dataDir, cloudURL string, authSvc auth.Service)` wires prefs + queue + engine, building the api upstream from `authSvc.TokenSource` (degraded — no engine — without a data dir, or without a cloud URL + a non-nil token source). `Start(ctx)` runs the settings-sync engine (idempotent — a second `Start` is a no-op so it can't leak an engine goroutine) **plus a goroutine that observes the auth session `State` and pokes the engine only when `Authenticated` flips** (sign-in → authenticate + sync now; sign-out → cancel the in-flight authenticated watch). The stream is latest-value (current-on-subscribe), so the goroutine seeds its baseline from the first `State` without poking, and a routine token refresh — which leaves `Authenticated` unchanged — never wakes the engine. Tracking the single `Authenticated` bit (not the whole `State`) is what makes refresh a non-event, so the old "poke on any state ≠ the last seen" dance (which compared the whole state, incl. tokens, and so fired on refresh) stays gone. `Close()` stops the engine **and** the poke goroutine. Exposes `Prefs()` (the settings store, nil when degraded). The required production inputs are positional constructor args (`dataDir`, `cloudURL`), not a config struct; the test seam (a fake sync upstream instead of the api client) is an **unexported functional option** — `withUpstream`, applied by an unexported `newWithOptions(dataDir, cloudURL, authSvc, opts...)` builder that `New` wraps and reachable only from `cloud`'s own (white-box) tests, mirroring the `auth` subsystem's option pattern.

Sub-packages (each TDD'd in isolation, leaf-first):

- `internal/cloud/syncstore` — generic `Envelope[T]{Data, Version, LastSyncedAt, LastEventAt}` + `Store[T]` over `internal/atomicjson` (crash-safe JSON; serialized writers). The reconcile-state file primitive.
- `internal/cloud/prefs` — the `Settings` type (**pointer fields + omitempty** so absent ≠ cleared, for the cloud's deep-merge), `Merge(base, patch)` (the local-first reconcile primitive), `Clone` (deep copy), and `Store` (persist + a `gochan/watch` hub that publishes current-on-subscribe, with an equality guard so an unchanged `Set` neither writes disk nor publishes). Because `Settings` holds pointers, the `Store` (Set/Get) and the `mutationqueue` (Enqueue/Pending) **deep-copy at their boundaries** so a caller mutating a string it passed in (or one it got back) can't desync in-memory state from the persisted JSON or queued payload.
- `internal/cloud/mutationqueue` — durable FIFO of pending local patches (atomicjson-backed, monotonic non-random ids). `Enqueue`/`Pending`/`Ack`; survives restart so offline edits still reach the cloud.
- `internal/cloud/api` — minimal GraphQL-over-HTTP cloud client (POST + SSE `WatchSettings`), authenticating every request from a per-request `oauth2.TokenSource` built from a `func(context.Context) oauth2.TokenSource` factory (`auth.Service.TokenSource`), reading its `AccessToken` — not a per-call token threaded through.
- `internal/cloud/prefsync` — the always-on reconcile `Engine` + `Upstream` interface (`Snapshot`/`Watch`/`Update`). `Watch` returns the settings channel **plus a buffered terminal-error channel** (nil = clean end / ctx cancel; non-nil = a read/transport failure **or** a GraphQL subscription error frame, which ends the stream rather than being silently skipped) so the engine distinguishes an errored close (record `LastError`, keep escalating backoff) from a healthy one — a nil error channel is treated as a clean end. Supervised connection with exponential backoff + poke + wall-clock wake detection (injectable `Now`/`Sleep`/`Jitter` seams for deterministic tests). `Set` is **local-first** (write store + enqueue + poke); on Live it **drains the queue** via `Upstream.Update` and acks; incoming snapshots/events have **still-pending patches re-layered on top** (`prefs.Merge`) so a stale cloud snapshot can't clobber an unacked local edit.

## gRPC + GraphQL over one socket (h2c)

gRPC needs HTTP/2; GraphQL stays HTTP/1.1. `internal/app` wraps the GraphQL/control mux in `h2c.NewHandler` whose dispatcher routes requests matching `grpcserver.IsGRPCRequest` to the `*grpc.Server` and everything else to the mux. The predicate lives in `grpc/` because it *is* the definition of a gRPC request (HTTP/2 *and* `application/grpc`); the composition root owns the dispatch + h2c wiring (the decision that these two surfaces share one socket). Each concern stays with its owner without a separate multiplexer package — `grpc/` owns "what is a gRPC request", `app` owns the topology. HTTP/1.1 GraphQL POST + SSE are untouched (they keep `ProtoMajor==1` and a Flusher-backed writer). An idle `Watch` stream is kept alive under the server's 60s `IdleTimeout` by a gRPC keepalive ping. The gRPC `KubeContextService` and the GraphQL `kubeConfigWatch`/`setCurrentContext` resolvers share the one `KubeConfigWatcher`, so a change via either transport fans out to both. The webview uses GraphQL; the host (tray) uses gRPC.

**Shutdown** is driven through the `App` surface from `main.go`. `srv.RegisterOnShutdown(app.NotifyShutdown)` fires the moment `srv.Shutdown` begins, then:

1. **`app.NotifyShutdown()`** fans out to both sub-servers: `grpcServer.NotifyShutdown()` cancels the serving context (every `Watch` handler returns `nil` → grpc writes its OK trailers → each client sees a clean `io.EOF`), and `graphqlServer.NotifyShutdown()` closes a `shutdownCh` that cancels each active SSE subscription's request context (gqlgen flushes its terminal `event: complete`).
2. **`srv.Shutdown(ctx)`** stops accepting and waits for the non-hijacked GraphQL requests to finish — the SSE streams, now cancelled, flush and return.
3. **`app.DrainWithContext(ctx)`** waits on *both* sub-servers' `WaitGroup`s. This is the essential wait for the **hijacked h2c gRPC streams** that `srv.Shutdown` does not track; for GraphQL it's belt-and-suspenders.
4. **`app.Close()`** stops the gRPC transports (`grpcServer.Stop()`), stops the cluster-cache coordinator (and shuts down the per-cluster cache pool, bounded), and closes the kube-config watcher.

Why it's built this way (the non-obvious parts): grpc's own `GracefulStop` **panics** on the `ServeHTTP`/h2c path, so the stream must end on its own serving context instead, and `Stop` only runs in step 4 after the streams have drained. The GraphQL SSE drain is **per-request** (`graph.Server.ServeHTTP` wires each SSE request's context to `shutdownCh`), deliberately **not** via `http.Server.BaseContext`: a `BaseContext` cancel would tear down the shared h2c connection carrying gRPC mid-stream. Because nothing touches `BaseContext`, the two transports are independent — `NotifyShutdown` signals both at once and there is no required gRPC-before-GraphQL ordering. (The h2c dispatcher also routes gRPC away *before* the GraphQL server's `ServeHTTP`, so a long-lived gRPC connection is never counted in the GraphQL `WaitGroup`.)


## Patterns

- **Nil-tolerant resolver**: a bare `&graph.Resolver{}` (used by tests / minimal surfaces) must not panic. `graph.NewServer` defaults a nil `ClusterData` to a Reader over a nil registry (empty snapshots, closed watches); resolvers nil-guard their other optional deps (e.g. `KubeConfigWatch`, `SetCurrentContext` guard `KubeConfigWatcher == nil`; the cluster mutations/`clustersWatch` guard `ClusterManager == nil`). Preserve this when adding resolvers.
- **Pub/sub**: `github.com/amorey/gochan` hubs fan snapshots to subscribers — `watch` for latest-value "current state" streams (the kubeconfig watcher and the auth session-`State` stream, both delivering the current snapshot on subscribe — a consumer needs no separate "read current" call to seed itself), `broadcast` for fan-out streams whose subscribers supply their own initial snapshot (the clustersync coordinator's merged-view hub). Watchers (`k8shelpers`) use fsnotify + a debounce, then publish the new snapshot.
- **Subscription resolvers**: return a channel that **emits the current snapshot first, then deltas** (see `streamWithSnapshot`, and the `kubeConfigWatch` / `clustersWatch` resolvers). Honor `ctx.Done()`. Degrade a missing source to an already-closed channel (e.g. `clustersWatch` with no `ClusterManager`) rather than erroring.

## Tests & checks

- testify + `net/http/httptest`. Resolver-level GraphQL tests stand up `graph.NewServer(&graph.Resolver{...})` and `POST /graphql` (in `graph/`); h2c/control/lifecycle tests stand up `app.New(...)` (in `internal/app/`). Filesystem via `t.TempDir()` / `os.MkdirTemp`.
- **White-box tests by default** — a package's tests live in the same `package foo` (not `package foo_test`), so they can exercise unexported helpers directly with no export-tax. This mirrors the flat-package philosophy elsewhere in the tree (e.g. `internal/auth`): boundaries inside a package are kept by discipline + file ownership, not by the compiler, and the test layer follows the same rule. **Escape hatch:** reach for an external `package foo_test` only when a test's *purpose* is to pin the public contract and you want the compiler to *guarantee* it touches only the exported surface — then say so in a comment. Don't mix the two styles within one package without that reason.
- **Avoid magic sleeps.** Don't `time.Sleep` to wait for async work (fsnotify reloads, hub publishes) — block on the actual event with `<-sub.Chan()` guarded by a `select { case … : case <-time.After(deadline): t.Fatal(…) }` timeout, as the watcher tests do. A `time.After` deadline is fine; a fixed sleep is flaky and slow.
- `make test-go` (`cd sidecar && go test ./...`).
- `make lint-go` (gofmt) and `make vet-go` (`go vet`). Run `gofmt -w` before committing.
