# sidecar — Go backend

A standalone Go binary started by the Tauri host. It exposes the app's GraphQL API (and a gRPC control channel) and owns all Kubernetes and kstack-cloud logic. **No TCP** — it listens on a Unix domain socket (named pipe on Windows), prints `READY unix:<path>` to stdout so the host can dial it, and shuts down on `SIGINT`/`SIGTERM` or **stdin EOF** (the host closing its end = "parent gone").

## Layout

The codebase mirrors the **kubetail layout**: `main.go` is lifecycle only, `internal/app` is the composition root + routing, and the GraphQL server lives in `graph` (alongside the resolvers). There is **no `server` package**; "the server" is the thin listener in `main.go`.

- `main.go` — **lifecycle only**. Parses flags, binds the socket, builds the `*app.App`, mounts it on an `http.Server`, registers `app.NotifyShutdown` via `srv.RegisterOnShutdown`, serves, and drives graceful shutdown (`srv.Shutdown` → `app.DrainWithContext` → `app.Close`). No composition logic.
- `internal/app/` — **composition root + routing + lifecycle owner**. `app.go` (`app.New(Config{...})`) builds the engine-shared instances (store, hub, sync engine, creds, kube-config watcher), constructs the `graph.Resolver`, wires the GraphQL server (`graph.NewServer`) and gRPC server (`grpcserver.NewServer`), mounts them plus the control endpoints on a mux, and multiplexes onto one h2c handler: an `h2c.NewHandler` whose dispatcher sends `grpcserver.IsGRPCRequest` traffic to the gRPC server and everything else to the mux. It owns this *composition* — that these two surfaces share a socket and the h2c wiring itself — while `grpc/` owns the gRPC-request predicate. `App` is an `http.Handler` owning `Start` (sync engine) and the `NotifyShutdown`/`DrainWithContext`/`Close` surface that fans out to the two sub-servers. `control.go` holds the **host-only control endpoints** (`/control/credentials`, `/control/wake`); `paths.go` holds the prefs-file layout helpers (`DefaultPrefsPath`, `SyncPath`).
- `graph/` — GraphQL: `schema.graphqls`, generated code, resolvers, and **`server.go`** — `graph.Server` (`NewServer(*Resolver)`), the gqlgen handler with the bearer-token plumbing, SSE shutdown lifecycle, and `NotifyShutdown`/`DrainWithContext` (see Shutdown below). A bare `&Resolver{}` is tolerated (nil `Sync` → Offline) so tests can stand up a minimal surface.
- `grpc/` — gRPC surface. `grpc/server.go`: `grpcserver.NewServer` wraps a `*grpc.Server` (registering `KubeContextService`, reusing `k8shelpers.KubeConfigWatcher`) with the `NotifyShutdown`/`DrainWithContext`/`Stop` lifecycle surface; the lower-level `New` stays exported for tests that drive the serving context directly. The predicate `IsGRPCRequest` (the "what is a gRPC request" rule — HTTP/2 *and* the gRPC content-type) lives here too, beside the gRPC server it defines; the composition root (`internal/app`) uses it in its h2c dispatcher to route the shared socket. `grpc/kubecontextpb/` holds the **committed** protoc output for the repo-root `proto/kubecontext.proto`. Regenerate with `make proto` (or `go generate ./grpc/...`); never hand-edit `*.pb.go`.
- `internal/` — building blocks: `app` (composition root, above), `ipc` (binds the per-OS IPC endpoint — AF_UNIX socket / named pipe — with user-only access; `main.go` uses `ipc.Listen`/`DefaultSocketPath`/`Scheme`), `k8shelpers` (kubeconfig watcher), `sync` (cloud sync engine), `syncstore` + `prefs` (local state), `hub` (pub/sub), `cloud`, `authcreds`, `mutationqueue`, `atomicjson`, `logging`, `sqlitemigrate` (shared forward-only SQLite migration runner), `appdb` (owns the app-level `app.db` — its connection pool and single migration sequence — and hands the `*sql.DB` to consumers), plus the **cluster cache** packages below.

## Cluster cache (per-cluster SQLite mirror)

A local SQLite mirror of every reachable Kubernetes cluster, so the GraphQL cluster-data surface answers from disk and never blocks on the live API, plus a durable registry of every cluster we've seen (so one survives in the UI after leaving the kubeconfig). Enabled only when the host passes `--data-dir` (env `KSTACK_DATA_DIR`) — the Tauri host wires its `app_local_data_dir()`; standalone/test runs omit it and the cluster resolvers degrade to empty results. Per-cluster DBs live at `<data-dir>/clusters/<cluster-uuid>.db` (UUID = the cluster's `kube-system` namespace UID, stable across context renames); the app-level `<data-dir>/app.db` (deliberately outside the `clusters/` dir, so the per-cluster cache scan doesn't mistake it for a `<uuid>.db` cache) holds the cluster registry — and is **owned by `internal/appdb`**, which opens it, holds its one migration sequence, and hands the `*sql.DB` to feature packages (a SQLite file has a single `schema_migrations` sequence, so its schema can't be co-owned; add a new app-level table as a numbered migration in `appdb/migrations/`, not as a second embed against the same file). Four cluster-cache packages:

- `internal/clustercache` — storage + lifecycle. `Manager` owns one `ClusterDB` (WAL: 1 writer conn, 4 reader conns) per UUID; `Open`/`Close`/`Shutdown`/`Lookup`, plus cache-file ops `CacheBytes`/`DeleteCacheFiles`/`ScanCachedUUIDs` (all cover the `["", "-wal", "-shm"]` file group). (`Manager` is not a DB connection pool — each `ClusterDB` holds the real read/write `*sql.DB` pools; the `Manager` is the keyed set of those per-cluster DBs.) `ClusterDB.Subscribe()/Notify()` is the change-notifier the watch resolvers + the Coordinator's freshness tracker ride. Migrations under `migrations/*.sql` (embedded), applied by the shared `internal/sqlitemigrate` runner. `Open` starts the cluster's `Upstream.Run` sync goroutine per cluster plus a janitor (TTL sweep). Pure-Go driver (`modernc.org/sqlite`, no CGO).
- `internal/clusterregistry` — the **durable registry**. A small `clusters` table in the app-level `app.db` holding one `Record` per cluster: name, `Enabled`, and first-seen / last-synced / last-seen-in-kubeconfig timestamps. It is a **pure data-access layer**: `clusterregistry.New(*sql.DB)` takes the already-open, already-migrated handle from `internal/appdb` (it does not open or migrate the file, and must not close it); the table's schema lives in `appdb/migrations/`. SQLite is the source of truth, reads hit it directly. The Coordinator is the sole writer.
- `internal/k8ssync` — the **write path** + the cluster manager. `Upstream.Run` discovers GVRs and drives one client-go `Reflector` per list/watchable resource (built-ins + CRDs) into the universal `objects` table (+ a dedicated `events` table). The `raw_json` column (the full object) is stored **zlib-compressed** via `clustercache.CompressRaw` (the largest column, ~4-5x; deterministic, self-identifying by its `0x78` header so no version prefix) — read it back through `clustercache.DecompressRaw`. `objects` is a *mirror*, not a log, so it's bounded without a TTL: each reflector deletes rows on watch-delete events and reconciles via a per-kind delete-missing prune on relist (`objectsStore.Replace`). The one gap that prune can't cover — a kind that vanishes entirely from discovery (e.g. an uninstalled CRD), since no reflector runs for it — is closed by `pruneOrphanedKinds`, which `discoverGVRs` runs after a **complete** discovery (skipped on partial discovery, so a transiently-unavailable API group isn't mistaken for a removed one) to evict `objects` rows whose `(kind, api_version)` is no longer discovered, cascade rows included. `Coordinator` keeps the registry, store and kubeconfig in lockstep: on every `KubeConfigWatcher` snapshot it `RecordSeen`s each reachable context (identified by `probeClusterUID`), opens clusters that are **present ∧ enabled**, freezes the rest, and backfills orphaned cache files on first run. It implements `k8ssync.Manager` (the cluster read+control surface, held by the resolver as its `ClusterManager` field) — the merged `ClusterView` read surface (`Clusters`/`CurrentContext`/`Subscribe`) plus the `SetEnabled`/`DeleteCache` mutations (serialized with reconcile by an action-mutex). A per-open-cluster goroutine stamps freshness on each `Notify`, flushed to the store on a ~30s ticker. Discovery is live — a kubeconfig edit or a toggle reconciles without a restart. Kubeconfig **presence is name-based** (a context still in the kubeconfig stays present even when its UID probe transiently fails, so an outage doesn't orphan a live cluster); for an already-open cluster whose resolved `rest.Config` changes (rotated token/cert, new endpoint — detected via a config fingerprint) reconcile **restarts** that cluster's sync so reflectors pick up the new credentials. When two contexts resolve to one cluster UUID the current-context alias wins deterministically. The sync goroutine in `clustercache` **retries with backoff** if `Upstream.Run` returns while the cluster is still open. A kubeconfig context whose UID probe has **never** succeeded (a stopped/unreachable cluster, e.g. minikube not running) has no UUID and thus no registry record, so `buildViews` synthesizes a **pending** `ClusterView` for it — `Present` true, empty `UUID`, `Cached`/`Enabled` false — so it shows in the UI as a not-yet-synced Active row rather than vanishing; it's replaced by the real (identified, cached) row once a probe succeeds. Pending names skip those already covered by a registry record (a previously-probed context now unreachable keeps its own row) and probed aliases.
- `internal/clusterdata` — the **read path** for resource data. `Reader` turns `objects`/`events` rows into typed snapshots (`Pods/Services/Deployments/Nodes/Events`) + `Watch*` channels. It reads via `Registry.Lookup` (open-only-if-already-open), **never `Open`** — so a disabled (frozen) or absent cluster reads as empty and a read never starts a sync. All SQL lives here so `graph` stays a thin delegate-and-map shell; nil-tolerant.

The `graph` resolvers are one-line delegations: resource queries call `r.ClusterData.Pods(…)` etc.; `clusters`/`clustersWatch` map `ClusterManager.Clusters()` (`[]ClusterView`) → `model.*` via `graph/cluster_mappers.go` (using `streamWithSnapshot` for the subscription); `setClusterEnabled`/`deleteClusterCache`/`removeCluster` call `ClusterManager`. **`deleteClusterCache` (clear cache) vs `removeCluster` (forget) are distinct**: `DeleteCache` frees the on-disk cache files but **always keeps the registry row** (a present+enabled cluster re-syncs from scratch; otherwise the row stays, now uncached — including an orphan), while `RemoveCluster` deletes the cache files **and** drops the registry row entirely (meant for an orphan; a still-present context is re-discovered next reconcile). The composition root (`internal/app`) builds the cache pool + registry + coordinator when `DataDir != ""`, threads `ClusterData` (always non-nil) and `ClusterManager` into the `Resolver`, runs the coordinator in `Start`, and `Shutdown`s the cache pool in `Close`. (The frontend `cluster-sync-panel.tsx` renders `clustersWatch` as a grouped Active/Orphaned table and drives the three mutations from per-row action buttons; there is no separate per-cluster sync-status surface — status is derived from the `present`/`enabled`/`cached` flags, plus an empty `uuid` marking a still-unidentified "pending" context.)

## gRPC + GraphQL over one socket (h2c)

gRPC needs HTTP/2; GraphQL stays HTTP/1.1. `internal/app` wraps the GraphQL/control mux in `h2c.NewHandler` whose dispatcher routes requests matching `grpcserver.IsGRPCRequest` to the `*grpc.Server` and everything else to the mux. The predicate lives in `grpc/` because it *is* the definition of a gRPC request (HTTP/2 *and* `application/grpc`); the composition root owns the dispatch + h2c wiring (the decision that these two surfaces share one socket). Each concern stays with its owner without a separate multiplexer package — `grpc/` owns "what is a gRPC request", `app` owns the topology. HTTP/1.1 GraphQL POST + SSE are untouched (they keep `ProtoMajor==1` and a Flusher-backed writer). An idle `Watch` stream is kept alive under the server's 60s `IdleTimeout` by a gRPC keepalive ping. The gRPC `KubeContextService` and the GraphQL `kubeConfigWatch`/`setCurrentContext` resolvers share the one `KubeConfigWatcher`, so a change via either transport fans out to both. The webview uses GraphQL; the host (tray) uses gRPC.

**Shutdown** is driven through the `App` surface from `main.go`. `srv.RegisterOnShutdown(app.NotifyShutdown)` fires the moment `srv.Shutdown` begins, then:

1. **`app.NotifyShutdown()`** fans out to both sub-servers: `grpcServer.NotifyShutdown()` cancels the serving context (every `Watch` handler returns `nil` → grpc writes its OK trailers → each client sees a clean `io.EOF`), and `graphqlServer.NotifyShutdown()` closes a `shutdownCh` that cancels each active SSE subscription's request context (gqlgen flushes its terminal `event: complete`).
2. **`srv.Shutdown(ctx)`** stops accepting and waits for the non-hijacked GraphQL requests to finish — the SSE streams, now cancelled, flush and return.
3. **`app.DrainWithContext(ctx)`** waits on *both* sub-servers' `WaitGroup`s. This is the essential wait for the **hijacked h2c gRPC streams** that `srv.Shutdown` does not track; for GraphQL it's belt-and-suspenders.
4. **`app.Close()`** stops the gRPC transports (`grpcServer.Stop()`), stops the sync engine (bounded), and closes the kube-config watcher.

Why it's built this way (the non-obvious parts): grpc's own `GracefulStop` **panics** on the `ServeHTTP`/h2c path, so the stream must end on its own serving context instead, and `Stop` only runs in step 4 after the streams have drained. The GraphQL SSE drain is **per-request** (`graph.Server.ServeHTTP` wires each SSE request's context to `shutdownCh`), deliberately **not** via `http.Server.BaseContext`: a `BaseContext` cancel would tear down the shared h2c connection carrying gRPC mid-stream. Because nothing touches `BaseContext`, the two transports are independent — `NotifyShutdown` signals both at once and there is no required gRPC-before-GraphQL ordering. (The h2c dispatcher also routes gRPC away *before* the GraphQL server's `ServeHTTP`, so a long-lived gRPC connection is never counted in the GraphQL `WaitGroup`.)

## GraphQL via gqlgen — the schema is the source of truth

`graph/schema.graphqls` is authoritative — it is **also consumed by the frontend's codegen** (`codegen.ts` at the repo root). After editing it:

```sh
cd sidecar && go run github.com/99designs/gqlgen generate
```

This rewrites `graph/generated.go` + `graph/model/models_gen.go` and **appends resolver stubs** (panicking `not implemented`) to `graph/schema.resolvers.go` — implement those. **Never hand-edit `generated.go` / `models_gen.go`.** `tools.go` pins gqlgen so the command works on a fresh checkout. (Also re-run the frontend `pnpm codegen` after schema changes.)

## Patterns

- **Nil-tolerant resolver**: a bare `&graph.Resolver{}` (used by tests / surfaces that don't run the engine) must not panic. `graph.NewServer` defaults a nil `Sync` to an Offline `noopStatus`; resolvers nil-guard their optional deps (e.g. `KubeConfigWatch`, `SetCurrentContext` guard `KubeConfigWatcher == nil`). Preserve this when adding resolvers.
- **Pub/sub**: `internal/hub` and `github.com/amorey/gochan/watch` hubs fan snapshots to subscribers. Watchers (`k8shelpers`) use fsnotify + a debounce, then publish the new snapshot.
- **Subscription resolvers**: return a channel that **emits the current snapshot first, then deltas** (see `streamWithSnapshot`, and the `kubeConfigWatch` / `clustersWatch` resolvers). Honor `ctx.Done()`. Degrade a missing source to an already-closed channel (e.g. `clustersWatch` with no `ClusterManager`) rather than erroring.
- **Single-writer sync engine** (`internal/sync`): it owns the only cloud connection. Reads are served from the local `syncstore` and never touch the network; write-through mutations publish to the hub and let the engine persist on the cloud echo.

## Tests & checks

- testify + `net/http/httptest`. Resolver-level GraphQL tests stand up `graph.NewServer(&graph.Resolver{...})` and `POST /graphql` (in `graph/`); h2c/control/lifecycle tests stand up `app.New(...)` (in `internal/app/`). Filesystem via `t.TempDir()` / `os.MkdirTemp`. Prefer **hand-written fakes** over generated mocks.
- **Avoid magic sleeps.** Don't `time.Sleep` to wait for async work (fsnotify reloads, hub publishes) — block on the actual event with `<-sub.Chan()` guarded by a `select { case … : case <-time.After(deadline): t.Fatal(…) }` timeout, as the watcher tests do. A `time.After` deadline is fine; a fixed sleep is flaky and slow.
- `make test-go` (`cd sidecar && go test ./...`).
- `make lint-go` (gofmt) and `make vet-go` (`go vet`). Run `gofmt -w` before committing.

When you change the sidecar's schema workflow, wiring, or conventions, update this `CLAUDE.md` in the same change.
